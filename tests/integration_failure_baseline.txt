# Integration tests known to fail, gated by scripts/check_integration_baseline.py.
#
# READ THIS BEFORE ADDING A LINE.
#
# This file exists because of a measurement failure, not a quality decision.
# The integration suite could never run: conftest.py's
# `start_epistemic_graph_server` falls back to `cargo build --features full`
# inside a fixture, and fixture setup runs inside pytest-timeout's per-test 60s
# window, so a cold cargo target produced ~500 `Timeout (>60.0s)` errors. Every
# one was about the build. None was about the code. Building the engine before
# pytest (see the `pytest` hook in .pre-commit-config.yaml) made the suite
# execute for the first time on 2026-08-21: 513 passed, 17 failed.
#
# Those 17 were then diffed against origin/main file by file. Every failing test
# module, and every source it exercises, was byte-identical there — the sole
# difference in that area, src/server/mutation_batch.rs, is pure rustfmt. They
# are pre-existing debt the timeouts had been masking, so gating every push on
# them blocks releases on a backlog no branch introduced. That is the same
# situation the merge queue already answers by gating differentially against a
# base ref, and this file is the same shape as protocol_unbound_baseline.txt.
#
# The gate is NOT a mute button:
#   - a test failing that is NOT listed here fails the gate (regression),
#   - a test listed here that starts PASSING fails the gate until its line is
#     removed (the ratchet only tightens),
#   - an entry past its review-by date fails the gate.
# Its one honest limitation: it tracks WHICH tests fail, never why, so a
# baselined test whose failure mode changes stays baselined.
#
# Format, one per line:
#   <pytest-node-id>  # owner=@handle review-by=YYYY-MM-DD [note=tag]
