# EG-HYBRID-STORAGE requirements

| ID | Requirement | Verification |
|---|---|---|
| `EG-HYBRID-STORAGE-R001` | **Capability partition taxonomy.** Model: `crates/eg-types/src/capability_partition.rs` maps each wire operation class to one disposition. The classes are point lookup, structure operation, SQL analytic read and SQL OLTP DML. They also include graph traversal, vector search, time-series rollup, hybrid join, schema DDL, change-stream reads and as-of reads. The dispositions are `columnar`, `row`, `either` and `engine_only`. Behavior: every control-plane and graph class is `engine_only`. Refusal: an unknown class name refuses with `PARTITION_CLASS_UNKNOWN`. Evidence: a round trip of every class and the disposition matrix. | `crates/eg-types/tests/capability_partition.rs::matrix_round_trips_and_control_plane_is_engine_only` checks every class and one unknown name. |
| `EG-HYBRID-STORAGE-R002` | **Plan-level query router.** Model: the router decides per statement after table resolution. It reads placement, plan shape and cardinality estimates. The outcome is a closed set: `columnar`, `row`, `federated`, `native` or a typed refusal. Behavior: the decision is pure and deterministic. The plan cache of EG-DURABLE-KERNEL-R041 keeps it, keyed by statement digest, schema version and placement digest. Each routed result carries a `routed_to` receipt. Wiring: the router sits after table resolution in the SQL and UQL path. The R011 gate runs first. Refusal: a statement on an unknown table refuses before routing. | `crates/eg-query/tests/route_decision.rs::matrix_routes_and_cache_reuses` checks the four outcomes and one cache hit. |
| `EG-HYBRID-STORAGE-R003` | **Placement catalog and single DDL authority.** Model: `PlacementRecord{table, placement_class, row_ready_digest, fence_high_water, driver_id, receipt}` in `crates/eg-types`. The classes are `columnar_resident`, `row_resident`, `row_projected` and `lake_cold`. Behavior: the placement record commits in the same owner write as the catalog change. The row engine schema is a derived copy of the catalog. The row engine never accepts DDL from another path. Wiring: the served `PlaceTablePlacement`, `GetTablePlacement` and `ListTablePlacements` methods. Refusal: a placement change on an unknown table refuses. A DDL statement sent straight to the row engine is refused by the R017 roles. | `tests/test_hybrid_placement_served.py::test_placement_commits_with_catalog` places one table, replays the request and reads one receipt. |
| `EG-HYBRID-STORAGE-R004` | **Single admission authority for row writes.** Model: every write to a row-resident table enters the engine admission path and commit protocol. The row transaction is one participant. Behavior: the engine assigns the commit sequence. The commit record and the outbox envelope land in one engine transaction before the acknowledgment. The row engine applies the envelope through R015. Refusal: a write that bypasses admission has no role to write with under R017. Evidence: a fixture write behaves the same on both placements. | `tests/test_hybrid_row_write_served.py::test_row_write_admitted_once` writes, replays and compares with the columnar placement. |
| `EG-HYBRID-STORAGE-R005` | **Fence record and cross-engine consistency.** Model: the fence record is `(published_commit_seq, published_at, applied_set_digest)` in the row engine. Only a fence injection inside a committed row transaction advances it. Behavior: a row is visible only at or below the published fence. The reconcile check compares the applied set with the engine committed set. It runs at boot, every 60 s and before promotion. Refusal: a reconcile mismatch stops row routing for the table. Evidence: the fence visibility test and the reconcile mismatch test. | `crates/eg-rowstore/tests/fence.rs::visibility_and_reconcile` checks visibility at the fence and a seeded mismatch. |
| `EG-HYBRID-STORAGE-R006` | **Secondary-index contract.** Model: the catalog declares each secondary index of a user table: columns, uniqueness, partial predicate and driver. The row engine maintains each index as a derived structure. Behavior: an index probe on a row-resident table routes to the row engine. An index whose definition digest differs from the catalog falls back to the columnar engine. Refusal: an index declaration on a column absent from the table refuses. Evidence: the probe route test and the digest fallback test. | `tests/test_hybrid_index_served.py::test_probe_routes_and_digest_falls_back` probes a declared index and a drifted one. |
| `EG-HYBRID-STORAGE-R007` | **Projection pipeline over the committed stream.** Model: a row-projected table reads only the committed stream of the engine. It has no second write loop. Behavior: the projection consumer reads committed envelopes through the existing outbox contract. It keeps a per-table cursor. It supports reject, rebuild and rewind as a mirror target does. Refusal: the projection refuses an envelope whose schema digest differs from the catalog. Evidence: the caught-up digest equals the engine digest for the table. | `tests/test_hybrid_projection_served.py::test_projection_catches_up_to_digest` writes 1,000 rows and compares digests. |
| `EG-HYBRID-STORAGE-R008` | **Backfill and row-ready gate.** Model: a promotion to row-resident runs a bounded, resumable backfill from the engine rows. Behavior: backfill pages are bounded by rate and size. A crash resumes from the stored cursor without a repeat of finished pages. The table is row-ready only when the source snapshot digest equals the target load digest. Refusal: before row-ready, the router sends reads to the columnar engine and refuses row writes with `TABLE_NOT_ROW_READY`. Evidence: the digest gate test and the crash resume test. | `tests/test_hybrid_backfill_served.py::test_backfill_resumes_and_gates` crashes mid-backfill and checks the gate. |
| `EG-HYBRID-STORAGE-R009` | **Shadow-read parity before cutover.** Model: before reads of a table route to the row engine, a bounded shadow window reads on both engines. Behavior: the router compares the result digests of each shadow read. Cutover needs a complete window with zero mismatches. A mismatch records the statement digest and both result digests. It resets the window. Refusal: a cutover on an incomplete window refuses. A shadow error never counts as a match. Evidence: the window state tests. | `crates/eg-query/tests/shadow_window.rs::mismatch_resets_and_error_is_not_match` checks each window state. |
| `EG-HYBRID-STORAGE-R010` | **Degradation and failover semantics.** Model: an unavailable row engine degrades reads to the columnar engine with a typed `degraded` marker. Behavior: the degraded read runs only while columnar rows of the table remain. Otherwise the read refuses. Row writes obey the declared durability class. No write moves to another engine authority. Recovery runs the R005 reconcile before row routing resumes. Refusal: a degraded read that shows uncommitted data refuses. A durability-class downgrade under failure refuses. Evidence: the failover and recovery tests. | `tests/test_hybrid_failover_served.py::test_degrade_refuse_and_recover` stops the row engine and restarts it. |
| `EG-HYBRID-STORAGE-R011` | **Workload-class extension and per-listener route gate.** Model: the closed workload-class vocabulary of EG-DURABLE-KERNEL-R037 gains OLTP and analytic shapes under SQL. The point and structure split stays. Behavior: every wire listener sends its operation names through the one classifier. The dispatch gate alone decides session allocation and engine route. An OLTP operation on a row-resident table allocates no columnar session. Refusal: an unknown operation kind refuses. No listener routes without the classifier. | `crates/eg-query/tests/workload_class.rs::oltp_on_row_table_allocates_no_session` checks the route and one cache hit. |
| `EG-HYBRID-STORAGE-R012` | **Mixed-batch boundary: typed refusal and coordinated-commit seam.** Model: a write batch over row-resident and columnar-resident tables is a cross-store scope of EG-DURABLE-KERNEL-R034. Behavior: until the cross-store commit lands with its fault proof, the engine refuses a mixed batch before effect with `MIXED_PLACEMENT_BATCH`. The error names both placements. A single-store batch always takes the direct commit path. Evidence: the refusal test and the direct-path test. The coordinated commit is a later child with its crash matrix. | `tests/test_hybrid_mixed_batch_served.py::test_mixed_batch_refuses_pre_effect` submits one mixed and one single-store batch. |
