# EG-UNIFIED-DATA-PLANE requirements

| ID | Requirement | Verification |
|---|---|---|
| `EG-UNIFIED-DATA-PLANE-R001` | **Record attached-source and native-hosting architecture decisions.** EG documents, as approved architecture decision records, that attached third-party sources are the default integration path, that EG remains the single converged query engine, that native hosting is earned per application through a defined gate, the router's consistency contract, and the scope boundary of the pgrx companion. | Review of the merged architecture decision records confirms each decision is recorded and accepted. |
| `EG-UNIFIED-DATA-PLANE-R002` | **Unify attached-source registration into one owner-scoped registry.** EG provides a single owner-scoped attached-source registry that replaces the separate eg-plan ForeignSourceSpec::Sql, OBDA external_sources, and kernel mirror-target registrations, backed by a dialect-adapter contract covering the driver, SQL rendering, catalog reader, change capture, and type map. Credentials are resolved only by secret reference, and registration verifies the outbound target before persistence. | Integration tests show SQL, OBDA, change capture, and mirror paths all resolve through the same registered source, and registration of an unverified or cross-owner endpoint fails closed. |
| `EG-UNIFIED-DATA-PLANE-R003` | **Extract typed, hashed catalog graphs per dialect.** Each dialect adapter's catalog reader extracts tables, columns, keys, foreign keys, indexes, views, enums, and JSON columns into a versioned, typed, hashed schema graph, and every catalog artifact has a named OBDA or schema_context consumer. | A golden test confirms repeated catalog reads against the same source produce a stable hash and ordering. |
| `EG-UNIFIED-DATA-PLANE-R004` | **Infer schema structure deterministically from attached catalogs.** EG profiles attached-source columns and infers JSON shapes under a bounded, policy-gated sampling budget, discovers inclusion and functional dependencies with supporting evidence, and groups related tables using Leiden community detection with a fixed seed. | A deterministic test fixture produces identical dependency and grouping results across repeated runs. |
| `EG-UNIFIED-DATA-PLANE-R005` | **Compile approved relational mappings to named R2RML virtual graphs.** EG proposes ontology mappings deterministically first, allows a model to suggest additional mappings as proposals only, and compiles approved mappings to R2RML stored as versioned, server-side named virtual graphs queryable by name from SPARQL, UQL, and REASON. | A test confirms an unapproved or model-only mapping cannot be queried, while an approved mapping answers a known query by name. |
| `EG-UNIFIED-DATA-PLANE-R006` | **Push down virtual-graph queries to source SQL.** EG renders joins across triples maps on the same source, aggregates, and ORDER BY/LIMIT into native source SQL using typed values rather than text casts, and shows any in-memory fallback explicitly in the query plan. | A differential test compares pushed-down query results against the native source and confirms EXPLAIN reports the fallback reason when pushdown is not possible. |
| `EG-UNIFIED-DATA-PLANE-R007` | **Federate attached tables as DataFusion table providers.** EG exposes attached tables as DataFusion TableProviders with dialect-aware sub-plan pushdown for projection, filter, limit, join, and aggregate operations, reusing the datafusion-table-providers and datafusion-federation crates where their license permits. | An integration test compares a federated query plan and result against direct execution on the source for each supported pushdown operation. |
| `EG-UNIFIED-DATA-PLANE-R008` | **Normalize change capture into a durable, replayable framework.** Each adapter emits ChangeEnvelope records into CdcHub, which persists a durable position per subscription, replays idempotently after restart, reports lag metrics with guardrails such as a WAL retention cap, and handles keyless tables explicitly. Catalog-drift detection re-runs schema intelligence and flags mappings that the drift breaks. | A fault-injection test stops and restarts capture mid-stream and confirms the replayed result matches a snapshot of the source, with drift detection flagging an affected mapping. |
| `EG-UNIFIED-DATA-PLANE-R009` | **Drive consumers from change capture idempotently.** Change events update the graph through approved mappings, refresh vector and full-text indexes, and emit CEP and outbox events, all idempotent on the source position so a replayed event produces no duplicate effect. | A replay test re-delivers the same change position and confirms each consumer's state is unchanged. |
| `EG-UNIFIED-DATA-PLANE-R010` | **Maintain an accelerated local copy of attached data.** EG maintains an optional cached virtual graph or columnar replica in eg-lake for attached tables, refreshed by change capture under a per-table acceleration policy. | A restart/failover test shows the accelerated copy reconverges to the source within its declared lag objective. |
| `EG-UNIFIED-DATA-PLANE-R011` | **Route queries by freshness across native, live, and accelerated paths.** The query router selects between the native store, a live source read, and the accelerated copy based on declared freshness policy, and a client requesting read-your-writes waits for its last committed source position up to a bounded timeout rather than returning a stale result. EXPLAIN reports the selected route. | A timeout test confirms a read-your-writes request either waits successfully or fails explicitly, never returning stale data silently, and EXPLAIN output is checked against the actual route taken. |
| `EG-UNIFIED-DATA-PLANE-R012` | **Govern write-back to attached sources.** EG writes back to an attached source only through an approved, idempotent path with an audit reservation, and prefers the application's own API over a direct write when the application declares business logic of its own. | A negative test confirms a write missing approval, an audit reservation, or idempotency is rejected before it reaches the source. |
| `EG-UNIFIED-DATA-PLANE-R013` | **Implement the Postgres attached-source adapter.** The Postgres adapter connects via sqlx/tokio-postgres, reads the pg_catalog, captures changes through pgoutput logical replication, and maps jsonb, array, enum, and pgvector types without loss. | A per-engine conformance entry compares EG's query and capture results against native Postgres for each covered type. |
| `EG-UNIFIED-DATA-PLANE-R014` | **Implement the MySQL and MariaDB attached-source adapters.** The MySQL and MariaDB adapters connect via sqlx mysql, read information_schema, capture changes through row-based binlog with GTID, and map each engine's types, with separate conformance entries for MySQL and MariaDB. | A per-engine conformance entry compares EG's query and capture results against native MySQL and against native MariaDB. |
| `EG-UNIFIED-DATA-PLANE-R015` | **Implement the SQLite file attached-source adapter.** The SQLite adapter extends eg-sqlite-format to cover WITHOUT ROWID tables, attaches a live application's database file read-only in a lock-safe manner, and captures changes by WAL-frame tailing where safe or by rowid/updated_at watermark polling otherwise. | A conformance test attaches a live SQLite fixture under concurrent writes and confirms no lock contention and correct change capture. |
| `EG-UNIFIED-DATA-PLANE-R016` | **Implement the Microsoft SQL Server attached-source adapter.** The SQL Server adapter connects via the tiberius driver, reads the sys.* catalog, renders T-SQL including TOP and OFFSET/FETCH pagination, and captures changes through CDC or Change Tracking polled by LSN. | A conformance entry compares EG's query and capture results against native SQL Server. |
| `EG-UNIFIED-DATA-PLANE-R017` | **Implement the ClickHouse attached-source adapter.** The ClickHouse adapter connects via its HTTP or native client, reads the system.* catalog, and supports federation and acceleration while explicitly declaring that it has no change-capture capability. | A conformance entry confirms federated query results match native ClickHouse and that capture requests return an explicit unsupported result. |
| `EG-UNIFIED-DATA-PLANE-R018` | **Implement the Oracle and Db2 attached-source adapters.** The Oracle and Db2 adapters query and read the catalog through their driver or ODBC, and capture changes through the Debezium bridge. | A conformance entry compares EG's query results against native Oracle and native Db2, and confirms captured changes match a Debezium-sourced change stream. |
| `EG-UNIFIED-DATA-PLANE-R019` | **Implement the MongoDB and DocumentDB attached-source adapter.** The MongoDB/DocumentDB adapter connects through its native driver, represents the inferred document JSON shape as its catalog, and captures changes through native change streams. | A conformance entry compares EG's query results and captured change stream against native MongoDB/DocumentDB. |
| `EG-UNIFIED-DATA-PLANE-R020` | **Federate Snowflake, BigQuery, DuckDB, and Iceberg sources.** EG federates queries to Snowflake, BigQuery, DuckDB, and Iceberg as read-only sources, extending the existing iceberg_federation.rs for Iceberg, and uses Arrow Flight SQL where the source offers it. | A conformance entry compares federated query results against each native warehouse or lake engine. |
| `EG-UNIFIED-DATA-PLANE-R021` | **Bridge Debezium Kafka events into ChangeEnvelope.** EG consumes Debezium change events from Kafka and converts them into ChangeEnvelope records for any Debezium-supported source, reimplementing Debezium's envelope semantics natively in EG. | A replay test feeds a captured Debezium event stream through the bridge and confirms the resulting ChangeEnvelope sequence matches the source's actual changes. |
| `EG-UNIFIED-DATA-PLANE-R022` | **Build a per-dialect conformance harness.** A conformance harness runs each adapter against a containerized matrix of supported engine versions, verifying that pushed-down query results equal the native source's result and that a change-capture replay equals a snapshot of the source. | The harness reports a green conformance entry per engine/version pair and a reviewed deviation for any known difference. |
| `EG-UNIFIED-DATA-PLANE-R023` | **Operate a shared CloudNativePG and MariaDB platform.** EG runs attached applications on a shared platform using CloudNativePG, grouping clusters by major version and required extensions, with a dedicated database and role per application, separate EG read and replication roles, wal_level set to logical, point-in-time recovery to object storage, scheduled restore drills, and local storage volumes. A separate shared MariaDB group serves MariaDB-based applications. | A restore drill independently recovers a cluster from its point-in-time recovery backup and confirms data matches the pre-restore state. |
| `EG-UNIFIED-DATA-PLANE-R024` | **Admit applications to the shared platform with rollback.** EG admits each application to the shared database platform one at a time, with a tested rollback path, and retires that application's prior ingest connector only after it is fully attached with parity. | An admission test for each candidate application confirms rollback restores the prior state and that the retired connector no longer writes. |
| `EG-UNIFIED-DATA-PLANE-R025` | **Evaluate a pgrx companion extension through a spike.** A pgrx-based companion extension spike evaluates running a slice of EG inside Postgres, covering SPARQL over tables, vector search, one time-series kernel, and a wait-for-position helper, concluding in an approved go/no-go architecture decision record. | The spike's results and the recorded decision are reviewed against its defined scope before further pgrx work is authorized. |
| `EG-UNIFIED-DATA-PLANE-R026` | **Run the Gramps native-hosting pilot phases P0 through P5.** The Gramps pilot records a baseline content digest, establishes a real-Postgres control with a captured driver statement corpus, runs that corpus unmodified against EG, fixes only proven gaps with a failing test first, verifies restore paths, and demonstrates schema understanding through an approved mapping and query. Split per the net-new rule (no phase-gate type existed on main): `.1` is the typed model (this requirement's rollup is LANDED only once every child is). | Each phase's exit artifact, as defined in the specification, is produced and reviewed before the next phase begins. |
| `EG-UNIFIED-DATA-PLANE-R026.1` | **`GrampsPilotProgress` is a typed P0-P5 phase gate refusing a wrong, unreviewed, or out-of-order exit.** `crates/eg-types/src/gramps_pilot_phase.rs` defines the closed `GrampsPilotPhase` order and each phase's required exit-artifact kind, `PhaseExitArtifact::validate` (refuses a mismatched artifact kind or a blank reviewer), and `GrampsPilotProgress::admits`/`next_phase`, which refuse admitting a phase before every earlier phase has a valid exit. | Verified by unit tests: a well-formed exit validates, a wrong artifact kind and an unreviewed exit are refused, a fresh pilot admits only P0, skipping ahead without a prior exit is refused, an invalid exit does not advance progress, and the full ordered exit sequence completes the pilot. |
| `EG-UNIFIED-DATA-PLANE-R027` | **Fix Postgres compatibility gaps proven by captured traffic.** EG implements each Postgres compatibility feature in its inventory only once captured application traffic proves it is needed, with a test that fails before the fix and passes after. | Each fixed feature has a committed test shown failing against the prior behavior and passing against the fix. |
| `EG-UNIFIED-DATA-PLANE-R028` | **Build the Postgres-equivalence differential harness.** A differential harness compares EG against real Postgres using the Postgres regression suite, SQLancer-style generated cases, and captured application traffic, recording any known difference as a reviewed, named deviation rather than a self-updating baseline. | The harness report lists every deviation with its owner and a reproducing fixture, and no deviation is auto-suppressed on a subsequent run. |
| `EG-UNIFIED-DATA-PLANE-R029` | **Expose a schema_context query surface.** EG exposes a schema_context query that answers what a table is, what joins to it, which ontology class and application it belongs to, and the impact of a change, following the same pattern as the existing code_context surface. | A query test against a known catalog fixture confirms schema_context returns the expected joins, class, application, and impact for a table. |
| `EG-UNIFIED-DATA-PLANE-R030` | **Resolve entities across attached applications.** EG proposes cross-application entity links among Gramps, Immich, Twenty, and Firefly using blocking, field similarity, and a Fellegi-Sunter model, and records each link as an owl:sameAs proposal that only becomes active once approved. | An entity-resolution fixture with true matches, false matches, and ambiguous candidates confirms no proposal is asserted as owl:sameAs before approval. |
| `EG-UNIFIED-DATA-PLANE-R031` | **Enforce consolidation safety across attached applications.** EG isolates each attached application by tenant and principal, exposes its data only through approved mappings, enforces quotas that bound the blast radius of one application's load or failure, and applies an explicit upgrade-coupling policy and admission criteria before adding another application. | A fault-isolation test confirms one application's failure or quota breach does not degrade another attached application's service. |
| `EG-UNIFIED-DATA-PLANE-R032` | **Run the Immich connector pilot phases I0 through I6.** The Immich pilot generates a version-pinned API client from a checked-in OpenAPI fixture, provides read-first MCP tools with approval-gated writes, registers the connector across every required release catalog, ingests assets and per-user people incrementally with no-op replay on a second run, resolves cross-application entity proposals, and adds health, lag, and upgrade-digest checks. | Each phase's fixture and test, as defined in the specification, passes, including the no-op replay and one-change incremental ingest tests. |
| `EG-UNIFIED-DATA-PLANE-R033` | **Cut over Gramps to EG-backed storage in production.** Gramps P6 moves the production family tree to EG-backed storage with a Postgres replica and a nightly independent XML export, keeps a 30-day read-only SQLite fallback available, and proceeds only after an explicit, separately recorded go-ahead following the P0 through P5 evidence. | A rehearsed failover test exercises the fallback path and confirms the nightly export and replica remain consistent throughout the 30-day observation window. |
| `EG-UNIFIED-DATA-PLANE-R034` | **Keep eg-core's build, Clippy, and generated contract suite green.** eg-core's root library compiles successfully, and Clippy passes cleanly with all features and targets enabled. The generated contract suite passes all of its cases, and the scanner/contract/catalog test suite passes all of its cases. | Continuous integration enforces a successful root library build, a clean all-features/all-targets Clippy run, and full passes of the generated contract and scanner/contract/catalog test suites. |
| `EG-UNIFIED-DATA-PLANE-R035` | **Share the compiled ontology cache with attached-schema graphs.** EG reuses the compiled shapes and ontology cache on every RDF write to a graph with an attached, non-core schema source, rather than recomputing the full parse-and-classification composition in icv_guard::compiled_policy on each write, matching the caching EG-TYPED-PACKS-R051 requires for core-schema graphs. | A benchmark test measures per-write latency on an attached-schema graph and confirms it matches cache-hit performance rather than full-recomputation performance. |
| `EG-UNIFIED-DATA-PLANE-R036` | **Derive HealthAnomaly and Incident facts with conformance checking.** EG's complex-event-processing pipeline derives HealthAnomaly and Incident facts from the data plane's change and telemetry events, and checks each derived fact against its declared-versus-observed conformance. | A test feeds a known event sequence through the pipeline and confirms the expected HealthAnomaly and Incident facts and conformance result are produced. |
| `EG-UNIFIED-DATA-PLANE-R037` | **Virtual-graph vocabulary is an EG core schema source.** EG ships `core:virtual-graph@1` with three classes: `SourceConnection`, `MetadataContract` and `VirtualMapping`. A `SourceConnection` carries a source kind, an endpoint reference and declared capabilities. Source kinds cover API, MCP, A2A, GraphQL, SQL, Iceberg, Teradata-style warehouses and SPARQL endpoints. A `MetadataContract` describes one source at one schema version under a content digest. It lists discovered entities, fields, relationships and operations. A `VirtualMapping` binds one ontology class to one discovered entity, with a key field and predicate-to-field pairs. SHACL shapes refuse an endpoint reference with credentials. They also refuse a mapping that names an undiscovered entity or field. Only an approved mapping serves reads. | Shape fixtures accept a valid connection, contract and approved mapping. They reject credential-bearing references, undiscovered fields and unapproved mappings at read time. |
| `EG-UNIFIED-DATA-PLANE-R038` | **Materialize metadata and hot subsets; virtualize the rest.** Metadata discovery runs for every registered source kind, not only SQL dialect catalogs. Discovery writes a versioned, hashed `MetadataContract` and never copies entity rows. Entity rows stay at the source by default and answer queries through approved virtual mappings. A mapping copies rows only under an acceleration policy. That policy needs the source `copy` capability, a declared hot-subset predicate and a freshness watermark. A missing watermark disables the copied route. EXPLAIN states whether each fragment ran live or from a copy. | Tests prove discovery writes metadata only, a cold mapping reads live, a hot mapping copies only its declared subset, and a stale watermark falls back to live reads. |
