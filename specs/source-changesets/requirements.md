# MEDULLA-SCM requirements

| ID | Requirement | Verification |
|---|---|---|
| `MEDULLA-SCM-R001` | **Content-addressed blob store.** Model: each file version is a sealed blob record. The record is keyed by its SHA-256 digest. Identical bytes store once. The blob is compressed. A read takes a digest and returns the bytes. Behavior: a second write of the same bytes returns the same digest. It adds no new storage. A changeset path points to a blob by digest only. Wiring: compose the existing content-addressed chunk store (`src/server/blob/store.rs`) and its bounded streaming facade (`src/server/blob/stream.rs`). Reuse the sealed create-only record guard of MEDULLA-DURABLE-KERNEL-R057. Refusal: the store refuses an overwrite of an existing digest. It refuses an unreadable digest with a typed error. Evidence: identical bytes return one digest. A digest readback equals the original bytes. | `tests/test_scm_blob.py::test_blob_stored_once_and_read_by_digest` stores two identical versions. It reads the blob back by digest. |
| `MEDULLA-SCM-R002` | **Changeset record.** Model: a changeset is `Changeset{id, repo, parents, author_principal, message, changed_paths, created_at, gate_verdicts}`. `changed_paths` is a list of `{path, op, old_blob, new_blob, mode}`. The op is add, modify, delete, or rename. The record stores only the paths that changed against the first parent. It costs O(change), never O(repository). Behavior: an append to a branch chain adds one record. A changeset with a parent names the parent head. The append is atomic with the branch head advance. Wiring: add the record type to `crates/medulla-types` as `source_changeset.rs`. Append through the branch commit path of MEDULLA-BRANCH-MERGE-R002. Refusal: the engine refuses a changeset with an empty path list. It refuses a parent not on the target branch chain. It refuses a digest the blob store cannot read. Every refusal leaves the chain unchanged. Evidence: a two-path changeset stores exactly two path entries. The chain readback returns the record unchanged. | `tests/test_scm_changeset.py::test_changeset_stores_only_changed_paths` writes a three-file repository state. It changes two files. It asserts one changeset with two path entries. |
| `MEDULLA-SCM-R002.1` | **Structured trailers on a changeset.** The changeset record must carry `trailers{spec_ids, fixes, withdraw, withdraw_reason}` as typed fields in `crates/medulla-types/src/source_changeset.rs`. The git import of R010 parses the `Spec:`, `Fixes:` and `Spec-Withdraw:` trailers into these fields. The git export writes them back unchanged. MEDULLA-SDLC-R001 and MEDULLA-SDLC-R005 read these fields. | `tests/test_scm_changeset.py::test_trailers_round_trip_through_git` imports a commit with three trailer kinds and exports it with an identical commit id. |
| `MEDULLA-SCM-R003` | **Lock-free acceptance.** Model: concurrent changesets on one branch are judged by their path sets. Disjoint path sets are accepted in parallel. Overlapping path sets trigger a server-side decision. Behavior: two writers on disjoint paths both land. No global lock gates either write. On overlap, the server rebases the late changeset on the new head. The rebase uses a file-level three-way merge at line granularity. It reuses the merge pass of MEDULLA-BRANCH-MERGE-R004. A clean rebase lands as the new head. An unclean overlap is refused with the stable `SOURCE_CONFLICT{paths}` code. The refusal lists every conflicting path. Wiring: compose the version-checked write path of MEDULLA-DURABLE-KERNEL-R084. Reuse the branch chain append of MEDULLA-BRANCH-MERGE-R002. Refusal: the engine refuses a changeset whose base left the branch chain. The refusal names the stale base. It never rebases silently. Evidence: two disjoint writers both land. Two overlapping writers land one and conflict the other. | `tests/test_scm_accept.py::test_disjoint_writers_land_and_overlap_rebases_or_conflicts` drives two concurrent writers on disjoint paths. It drives two on one shared path. It asserts one landing plus one typed conflict. |
| `MEDULLA-SCM-R004` | **Tree materialization by query.** Model: a tree is `Tree(repo, rev, prefix, depth)`. It returns entries of `{path, blob_digest, mode}`. The tree is computed from the changeset chain. Periodic snapshot checkpoints bound the replay length. Behavior: a subtree read at any revision returns the entries at that revision. The read costs O(subtree), never O(history). A prefix read returns only that prefix. A depth bound limits the walk. Wiring: add the tree query to `crates/medulla-compute` as `source_tree.rs`. Reuse the snapshot checkpoint path of MEDULLA-DURABLE-KERNEL-R023. Refusal: the engine refuses a revision not on the repository chain. It refuses a cross-tenant tree read. Both refusals are typed. Evidence: a tree read at revision N equals the full replay of changesets up to N. The checkpoint path returns the same entries. | `tests/test_scm_tree.py::test_tree_at_revision_matches_full_replay` builds a ten-revision chain. It reads a subtree at each revision. It asserts equality against a full replay. |
| `MEDULLA-SCM-R005` | **Derived history indexes.** Model: four derived indexes serve history. Path history lists the changesets that touched a path. Blame maps each line to its last changeset. Ancestry skip lists accelerate merge-base and ancestor queries. Change coupling pairs files that change together. Behavior: each index updates incrementally as changesets land. A revision replay appends and never rewrites. Every index carries a version and a rebuild recipe. A rebuild from the changeset chain reproduces the index byte-for-byte. Wiring: add `crates/medulla-compute/src/source_history.rs`. Reuse the incremental derived-series machinery of MEDULLA-REPO-INGEST-R004. Reuse the commit and change-coupling graph of MEDULLA-REPO-INGEST-R601. Refusal: the engine refuses an index read at a version past the index head. It refuses a cross-tenant history read. Evidence: incremental index state equals a from-scratch rebuild. A rebuild after corruption restores identical entries. | `tests/test_scm_history.py::test_incremental_indexes_equal_rebuild` applies a changeset sequence incrementally. It rebuilds the same indexes from scratch. It asserts byte-identical output. |
| `MEDULLA-SCM-R006` | **Code graph stays live with changesets.** Model: an accepted changeset is an input to the code graph. Only structurally changed files re-enter the pipeline. Behavior: the engine re-parses each structurally changed file. It updates fingerprints per MEDULLA-REPO-INGEST-R603. It updates symbols and tests per MEDULLA-REPO-INGEST-R600. It recomputes Leiden communities per MEDULLA-REPO-INGEST-R011. The community pass runs on the affected subgraph only. `code_context` and UQL answer from the new state as soon as the changeset lands. Wiring: attach to the incremental indexing boundary of MEDULLA-REPO-INGEST-R006.4. Reuse the existing enrichment and community-detector callers. Refusal: the engine refuses an indexing job whose base revision does not match. It follows the existing incremental-index refusal. Evidence: a one-file change updates only that file symbols. A structural no-op change updates nothing. | `tests/test_scm_code_graph.py::test_one_file_change_updates_only_its_symbols` lands a one-file changeset. It asserts the symbol graph updates for that file only. |
| `MEDULLA-SCM-R007` | **Path-scoped access control.** Model: a permission binds a path prefix, a principal, and a tenant. The permission carries separate read and write bits. Behavior: a read resolves the most specific prefix grant. A write requires a write grant on the path. The grant applies to tree, blob, changeset, and derived-index reads alike. Wiring: extend the universal read-RLS gate of MEDULLA-DURABLE-KERNEL-R029 with a path-prefix predicate. Reuse the existing tenant and principal resolution. Refusal: the engine refuses a read under a prefix with no read grant. It refuses a write with no write grant. It refuses a grant on a path outside the tenant scope. Evidence: a prefix grant filters reads to the prefix. A write outside the prefix is refused with a typed code. | `tests/test_scm_path_access.py::test_prefix_grant_filters_reads_and_refuses_writes` grants a prefix to one principal. It reads inside and outside the prefix. It attempts a write outside the prefix. |
| `MEDULLA-SCM-R008` | **Gate verdicts are records.** Model: a gate run records a verdict against a changeset. The record is `GateVerdict{changeset, gate_id, input_digest, verdict, evidence_digest, duration}`. The input digest binds the exact tree the gate read. Behavior: a landing policy reads the verdicts before it lands a changeset. A failed verdict blocks the landing. A verdict is sealed once written. Wiring: reuse the typed verdict model of MEDULLA-DURABLE-KERNEL-R089.1. Store the verdict under the sealed create-only guard of MEDULLA-DURABLE-KERNEL-R057. Refusal: the engine refuses a verdict whose input digest does not match the changeset tree. It refuses an overwrite of a sealed verdict. Evidence: verdict records read back byte-identically. A mismatched digest is refused. | `tests/test_scm_gate_verdict.py::test_verdict_records_are_sealed_and_read_back` records a pass verdict and a fail verdict. It reads both back. It attempts an overwrite and asserts the refusal. |
| `MEDULLA-SCM-R009` | **Bisect and revert decisions.** Model: a failed post-landing gate opens a bisect. The bisect walks the changeset chain from the failure back to the last good verdict. It uses recorded verdicts and on-demand gate runs. Behavior: the bisect identifies the culprit changeset. The engine then records a decision. The decision is a changeset revert or a fix-forward task. The decision record carries the evidence that produced it. Wiring: reuse the deterministic replay of committed decision records (MEDULLA-DECISION-ENGINE-R007). Store the decision with the existing decision-record authority. Refusal: the engine refuses a bisect whose chain lacks verdict coverage. It refuses a revert that later changesets depend on. Evidence: a bisect over a seeded chain names the seeded culprit. The recorded decision replays byte-identically. | `tests/test_scm_bisect.py::test_bisect_finds_culprit_and_replays_decision` seeds a failing change mid-chain. It bisects. It replays the recorded decision. |
| `MEDULLA-SCM-R010` | **Git import and export fidelity.** Model: a changeset maps one-to-one to a git commit. The export re-creates the commit with the same tree hash. An external git commit imports as a changeset. Behavior: an export of the full chain produces a git history. The history matches the changeset order and messages. A git import of that history reproduces the changeset chain. The round trip is lossless on commit ids and tree ids. Wiring: add `crates/medulla-compute/src/source_git_objects.rs`. It builds git objects from the tree entries. Refusal: the engine refuses an export whose tree read fails mid-stream. It refuses an import whose commit graph is malformed. Evidence: export then import preserves every commit id and tree id. | `tests/test_scm_git_round_trip.py::test_export_import_preserves_commit_and_tree_ids` exports a chain of twenty changesets. It imports the archive. It asserts identical commit and tree ids. |
| `MEDULLA-SCM-R011` | **Simulation harness.** Model: a hermetic simulation drives the accept path under stress. The simulation owns its clock and its failure injection. Behavior: the harness simulates concurrent writers with overlapping paths. It simulates a server rebase on a dirty base. It simulates a crash mid-accept and a full replay. It simulates export round trips at random intervals. It fuzzes changeset sequences against the same invariants. Wiring: add `tests/simulation/source_changesets.rs`. Drive the real accept, rebase, and tree paths. Refusal: the harness refuses a fuzz seed that fails to seed. A refused seed records no state. Evidence: every invariant holds across the full simulation matrix. A seeded regression fails the harness. | `tests/simulation/source_changesets.rs::simulate_concurrent_accept_crash_and_replay` drives concurrent accepts with crash and replay. It asserts chain invariants after every step. |
| `MEDULLA-SCM-R012` | **Agent-only principals and run provenance.** Model: an agent principal binds to a run. The binding is the RunTrace id of the run that produced the changeset. The changeset also records the agent identity. Behavior: an agent changeset carries both ids on acceptance. A human principal may omit the run trace id. The record is queryable by run, by agent, and by changeset. Wiring: attach to the changeset accept path of MEDULLA-SCM-R002. Reuse the RunTrace record authority already served by the engine. Refusal: the engine refuses an agent changeset with no run trace id. The refusal is typed. Evidence: an agent changeset reads back with its run trace id. A principal without a run id is refused. | `tests/test_scm_provenance.py::test_changeset_links_to_run_trace` submits an agent changeset with a run trace id. It reads the binding back. It submits one without and asserts the refusal. |
| `MEDULLA-SCM-R013` | **Graph-native code edits (rollup).** An agent must edit code as graph entities. It names a symbol and the new text. The engine projects the edit to file bytes and one changeset. A re-parse must confirm the round trip before the changeset lands. Children `.1` to `.7` deliver it. | See each child. |
| `MEDULLA-SCM-R013.1` | **Model.** Add `SymbolEdit{repo, branch, base_rev, ops, message, run_trace_id}` in `crates/medulla-types/src/source_symbol_edit.rs`. Each op is `{kind, symbol_id, anchor_span_digest, new_text}`. `kind` is a closed set: `replace_symbol`, `replace_body`, `insert_before`, `insert_after`, `delete`. | `crates/medulla-types/tests/source_symbol_edit.rs::edit_round_trips_and_kinds_are_closed` round-trips an edit and refuses an unknown kind. |
| `MEDULLA-SCM-R013.2` | **Projection.** Add `project_symbol_edit` in `crates/medulla-compute/src/source_symbol_edit.rs`. It resolves each symbol at `base_rev` to its path, blob digest and byte span. It applies the ops of one file in descending span order. Bytes outside the edited spans stay identical. It writes each new file version through R001 and builds one changeset of R002. | `crates/medulla-compute/tests/source_symbol_edit.rs::bytes_outside_spans_are_unchanged` edits one function and compares every other byte. |
| `MEDULLA-SCM-R013.3` | **Round-trip check.** The engine re-parses each changed file with `parse_file` at `crates/medulla-compute/src/parser/tree_sitter.rs:249`. The edited symbol must resolve with its qualified name and kind, unless the op is `delete`. Each untouched symbol must keep its structure hash of MEDULLA-REPO-INGEST-R603. An inserted symbol must be present. | `crates/medulla-compute/tests/source_symbol_edit.rs::reparse_confirms_edit_and_untouched_symbols` applies each op kind and checks the re-parse. |
| `MEDULLA-SCM-R013.4` | **Wiring.** Add the served method `SubmitSymbolEdit` beside `SubmitChangeset`. It calls `project_symbol_edit`, then the R003 accept path. The R006 re-index and the MEDULLA-SDLC-R001 derivation run on accept. arbora serves it as `source.edit_symbol` through `ARBORA-OPS-R848.4`. | `tests/test_scm_symbol_edit_served.py::test_symbol_edit_lands_and_reindexes` edits one symbol and reads the new `code_context` answer. |
| `MEDULLA-SCM-R013.5` | **Refusal.** A span digest that differs from the symbol at `base_rev` must refuse with `EDIT_BASE_STALE`. Overlapping ops in one file must refuse with `EDIT_OPS_OVERLAP`. A file that fails to re-parse must refuse with `EDIT_UNPARSEABLE`. A round-trip mismatch must refuse with `EDIT_ROUNDTRIP_MISMATCH{path, symbol}`. A refusal lands nothing. | `tests/test_scm_symbol_edit_served.py::test_symbol_edit_refusals` asserts each code and an unchanged branch head. |
| `MEDULLA-SCM-R013.6` | **Evidence.** The changeset records the `SymbolEdit` digest. Each op records the old and new span digests and the re-parse verdict. A readback must equal the written record. | `tests/test_scm_symbol_edit_served.py::test_symbol_edit_evidence_reads_back` compares every field. |
| `MEDULLA-SCM-R013.7` | **Hot-path proof.** The entry point is the served `SubmitSymbolEdit`. The benchmark `benches/source_symbol_edit.rs` edits one symbol in a 5,000-line file, including the re-parse. The p99 stays under 30 ms. Peak memory stays under 32 MiB. | `cargo bench --bench source_symbol_edit` fails on a 10 percent regression. |
