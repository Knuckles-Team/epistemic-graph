# EG-DECISION-ENGINE — Decision engine

## Outcome

Epistemic Graph (EG) evaluates typed decisions from caller-visible facts, records how each conclusion was reached, and can independently verify a committed result. Connector pack annotations enter that decision pipeline as **claims**, not proof of a capability. Consumers can assemble an agent graph, ask a statistical question, and inspect a certificate and evidence without relying on a private documentation service.

This specification owns EG's decision contracts, solver, evidence record and jobs. It defines the decision-facing semantics of published pack facts. Agent execution, connector discovery and ingestion orchestration are consumers. Their adapters may call these methods but cannot become a second authority for decision records or policy.

## Program state legend

Each requirement has two independent states. **Delivery:** `WAITING` means no reviewed source evidence; `IN_PROGRESS` means an implementation branch exists; `SOURCE_LANDED` means the exact implementation is reachable from published `main`; `RETIRED` means a recorded decision deliberately removed it. **Acceptance:** `NOT_RUN`, `FAILED`, `PARTIAL`, or `ACCEPTED` records test and release evidence for that exact published commit. A green unit test on a branch can support `IN_PROGRESS` but cannot imply `SOURCE_LANDED`; source landing cannot imply `ACCEPTED`. The coverage matrix below names scope, not a blanket acceptance claim. An evidence record must contain the commit, workflow run, test command, observed result and date. Rows with no current evidence remain `WAITING / NOT_RUN` until checked.

## Required behavior

1. **Decision ladder.** Filter by tenant and row visibility before feature extraction or counting. Apply policy, pins, denials and hard compatibility constraints; derive native ontology entailments; solve the legal set by bounded exact integer optimization; use fitted statistics only to rank legal options or abstain. Every answer exposes `resolution_kind` (`constraint`, `entailment`, `optimization`, `statistical`, `abstention`) and `evidence_class` (`proof`, `observation`, `claim`). The conclusion takes the weakest premise class. The derivation itself can be proof even when a pack-provided capability is a claim. Statistics can never authorize a denied option. (EH-001–003, EH-009, EH-013, EH-015–020, EH-050)
2. **Assembly and solver.** `AgentAssemble` accepts typed tasks/capabilities and constraints. EG derives capability closure and returns one legal `AgentGraphDraft` or a typed `AbstainReason`. The 0–1 model covers capability coverage, implications, exactly-one slots, compatibility, knapsack budgets, optional template shape and cardinality. Optimize lexicographically with checked integer arithmetic, deterministic branching and a work-node budget. There is no arbitrary answer-count cap. A certificate names feasibility, objective, lower bound, gap, solver version and input digest; a separate verifier recomputes them. Unknown cost, latency or capability facts cannot silently become zero or true. Bounded why-not re-solves explain excluded visible options. (EH-004, EH-008, EH-010–014, EH-018–019, EH-036, EH-049–054, EH-067, EH-072)
3. **Decision record and commit.** Records pin the request, visible candidate facts and provenance, ontology/policy/catalog/head digests, quantized feature matrix when used, solver identity, eliminated constraints, derivations, result and digest. `DecisionCommit` re-derives the result, verifies the certificate, checks every pinned component revision and compares the candidate-universe catalog digest within one Agent Library transaction. It stores a `DecisionRecord` component under `decision:<digest>`; a byte-identical retry is idempotent, while stale catalogs or fabricated inputs fail closed. Agent graph synthesis evidence references the committed record. Record versions remain decodable; unknown versions fail closed. Library-sourced records persist; graph-sourced statistical summaries use RLS-routed graph writes and policy-set retention. Maximum record size is 64 KiB, 64 candidates and 32 required capabilities, with typed size abstention. (EH-007, EH-012, EH-017, EH-019, EH-049, EH-053, EH-060, EH-067–071, EH-310)
4. **Statistics and evaluation.** `Decide` shortlists only caller-visible candidates, computes versioned features, separates full-label from bandit-label data, and records exact propensities. Calibration, conformal coverage, drift and selective-risk gates can abstain. Off-policy estimates report effective sample size and refuse promotion below policy thresholds. Training uses only independently evaluated, sufficiently traced outcomes from approved commit principals; self-reported outcomes are claims. Exploration requires an explicit budget and server HMAC seed, and is unavailable for policy, security, write-back and irreversible actions. `DecisionFit` emits a draft blob; `DecisionEval` emits a digest-bound receipt; only the guarded component publish path promotes a fitted head. Fixed-point/soft-float replay must produce identical bytes on supported targets. (EH-005–007, EH-016, EH-020–028, EH-040, EH-055–062, EH-068–074, EH-291–303, EH-395, EH-417, EH-523, EH-525, EH-528)
5. **Question families.** Reuse the same ladder for retrieval-plan choice, ingestion lane, enrichment scheduling, entity-resolution proposals, schema mapping, contradiction proposals, routing, risk, budget-aware option selection, connector event and tool proposals, A2A routing, context-bounded tool subsets, topology and finance recommendations. An advisory question returns a proposal and evidence only; execution and irreversible write-back still require their own deterministic authorization. `DecideText` has its own quote-aware, typed-parameter parser. (EH-029–045, EH-048, EH-064, EH-073, EH-214, EH-395, EH-403, EH-417, EH-452–464, EH-474, EH-694, EH-704)
6. **Pack fact admission.** Decision candidates come only from published, tenant-visible component revisions. Pack-provided capability, modality, schema digest, price, latency, model and `contract_pin` facts carry claim provenance. Unknown foreign capability IRIs remain exact claim terms; malformed native capability IRIs are refused upstream. Withdrawn components are ineligible. A stale ontology/shapes projection cannot supply current facts. Packs cannot publish `DecisionRecord`, `DecisionHead` or `DecisionPolicy` kinds. Re-import of identical content cannot change the decision candidate digest. (EH-052, EH-063, EH-111, EH-117, EH-128–136, EH-200)

## Acceptance boundary

`ACCEPTED` requires published-main contract generation, deterministic solver and verifier proof, served client requests, versioned replay vectors, negative authorization/visibility and pack-claim probes, and hosted CI at the exact commit. Each affected requirement ID gets its own evidence row; passing a train does not automatically close unrelated IDs. CCCC, jscpd (zero new clone pairs), Dupehound and KISS checks apply to changed code alongside formatting, Clippy, package tests and generated contract freshness. Hosted checks must provision disposable fixtures; credentials or an existing live deployment cannot be required to run the baseline PR gate. Optional deployment qualification is recorded separately.
