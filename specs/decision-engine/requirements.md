# EG-DECISION-ENGINE requirements

| ID | Requirement | Verification |
|---|---|---|
| `EG-DECISION-ENGINE-R001` | **Typed decision ladder with explicit resolution kinds (rollup).** Every decision answer exposes a resolution_kind of constraint, entailment, optimization, statistical, or abstention, selected by applying policy and hard constraints first, then ontology entailment, then bounded exact solving, and falling back to fitted statistics only to rank remaining legal options or abstain. Split (2026-10-09): `.1` the three resolution kinds the production chokepoint actually emits, `.2` the missing Constraint/Entailment production paths. | Unit and integration tests assert the resolution_kind returned for representative constraint, entailment, optimization, statistical, and abstention cases. |
| `EG-DECISION-ENGINE-R001.1` | **`ResolutionKind` is typed with all five variants; the production chokepoint emits Optimization, Statistical, and Abstention.** `ResolutionKind` (crates/eg-types) defines Constraint, Entailment, Optimization, Statistical, and Abstention. The live `Decide`/assemble chokepoint (`crates/eg-compute/src/assemble/conclude.rs`) constructs `ResolutionKind::Optimization` and `ResolutionKind::Abstention`; `stat_decide` constructs `ResolutionKind::Statistical` and `::Abstention`. | `crates/eg-compute/src/assemble/tests/routing.rs` and `crates/eg-types/src/test_support/contract_wave/decision.rs` assert resolution_kind for Optimization/Statistical/Abstention cases. |
| `EG-DECISION-ENGINE-R001.2` | **Remaining scope: production Constraint and Entailment resolution paths.** `conclude.rs` and `stat_decide` never construct `ResolutionKind::Constraint` or `::Entailment` — the only existing `Constraint` construction is `A2ARoutingResolution` (`crates/eg-types/src/decision/rapid_r044.rs`, EG-DECISION-ENGINE-R044.1), which is not wired into the general `Decide`/assemble chokepoint. Add: (a) a constraint-only short-circuit in `conclude.rs` that returns `ResolutionKind::Constraint` when hard constraints alone determine the answer, before solving/statistics run; (b) an ontology-entailment path that returns `ResolutionKind::Entailment` when the answer follows from entailment alone (reusing the existing is_a derivation machinery, EG-DECISION-ENGINE-R003). | Unit and integration tests assert `resolution_kind == Constraint` and `== Entailment` for representative cases through the production `Decide`/assemble chokepoint (not through `A2ARoutingResolution`). |
| `EG-DECISION-ENGINE-R002` | **Evidence class recorded on every decision record.** Every decision record carries an evidence_class of proof, observation, or claim. It takes the weakest premise class used in reaching the conclusion. So a pack-provided capability annotation is surfaced as a claim rather than a proof. | A negative test confirms that a capability derived only from an annotated claim is reported with evidence_class claim rather than proof. |
| `EG-DECISION-ENGINE-R003` | **Derivation records for entailed answers.** An is_a derivation record backs an entailment-resolved answer. It names the source and premise class of each edge used. An invented or unsupported ontology edge bars the overall answer from claiming proof-level evidence. | A negative test confirms the engine refuses an answer that depends on a fabricated ontology edge. The engine does not accept it as a proof. |
| `EG-DECISION-ENGINE-R004` | **Independently verifiable 0-1 integer solver certificate.** The solver in crates/eg-compute/src/solve produces a certificate naming feasibility, objective value, lower bound, optimality gap, solver version, and input digest for every solved assembly, and a separate verifier recomputes and checks that certificate independently of the solve path. | Determinism tests confirm repeated solves are byte-identical and match a committed golden certificate digest, and an exhaustive-search test confirms the solver's optimum matches brute-force search on small models. |
| `EG-DECISION-ENGINE-R005` | **Conformal and risk-controlled statistical guarantees.** Statistical heads apply acceptability-set conformal prediction, selective risk control (Learn-then-Test), and adaptive conformal inference to bound miscoverage under drift, abstaining rather than returning an uncalibrated answer when these guarantees cannot be met. | Numeric unit tests fit and evaluate each guarantee and assert the resulting coverage and abstention behavior. |
| `EG-DECISION-ENGINE-R006` | **Off-policy evaluation gated on effective sample size.** Decision evaluation records exact propensities and computes off-policy estimates using clipped or SWITCH importance sampling and doubly robust estimators, reporting effective sample size, and refuses to promote a fitted head when effective sample size falls below the configured minimum. | A unit test asserts that off-policy evaluation reports support and effective sample size and that promotion is blocked below the minimum threshold. |
| `EG-DECISION-ENGINE-R007` | **Deterministic cross-target replay of committed decision records.** A committed decision record replays to byte-identical quantized fixed-point digests using a pinned software floating-point implementation, so the same record verifies identically across the full set of supported target platforms. | A golden-vector replay test confirms identical digests on the supported targets, with the full target matrix exercised at release-qualification time. |
| `EG-DECISION-ENGINE-R008` | **Why-chosen and why-not explanations for solved assemblies.** Every solved assembly can explain why an option was chosen and, for a visible excluded option, why it was not, by performing a bounded re-solve per excluded option rather than an unbounded search. | Integration tests assert the why-not re-solve routing returns a correct, bounded explanation for excluded candidates. |
| `EG-DECISION-ENGINE-R009` | **Learned ranking stays monotone with respect to safety.** A fitted statistical head may only narrow the set of legal options or cause abstention; it can never widen the legal set or itself authorize an option that policy and hard constraints have not already permitted. | A negative test confirms that a learned head cannot override or widen the constraint-derived legal set, and that execution enforces this invariant independently of the head. |
| `EG-DECISION-ENGINE-R010` | **Typed abstention reason for unmet capability.** When no legal assembly satisfies the requested capabilities, the system returns a typed AbstainReason value naming the specific missing capability rather than a generic failure. | Unit tests assert that an unsatisfiable capability request returns an AbstainReason identifying the missing capability. |
| `EG-DECISION-ENGINE-R011` | **Work-budgeted search without an arbitrary result cap.** The solver in crates/eg-compute/src/solve/search bounds search by a deterministic node budget rather than an arbitrary cap on the number of candidate results, reporting an unresolved or certified-gap result when the budget is exhausted instead of silently truncating the option set. | Adversarial tests confirm that exhausting the budget above the accepted gap yields an unresolved result, that exhausting it within the accepted gap yields a certified gap, and that a parity case exhausts the budget without an incumbent. |
| `EG-DECISION-ENGINE-R012` | **Shared slate crediting across multiple questions.** When multiple questions are answered against the same assembly template, the system credits outcomes at the slot level across the shared template, with results aggregated consistently across the related questions. | Template-level unit tests assert slot-level crediting is applied correctly across a shared assembly template. |

| `EG-DECISION-ENGINE-R017` | **Single write authority per durable decision state kind.** Each kind of durable decision state, such as an assembled agent graph, a graph mutation batch, or a published component with its receipt, has exactly one write authority responsible for committing it, so no second code path can independently mutate that state. | Integration tests confirm that only the designated write path can commit each kind of durable decision state and that a bypassing attempt is rejected. |
