# EG-DECISION-ENGINE requirements

| ID | Requirement | Verification |
|---|---|---|
| `EG-DECISION-ENGINE-R001` | **Typed decision ladder with explicit resolution kinds.** Every decision answer exposes a resolution_kind of constraint, entailment, optimization, statistical, or abstention, selected by applying policy and hard constraints first, then ontology entailment, then bounded exact solving, and falling back to fitted statistics only to rank remaining legal options or abstain. | Unit and integration tests assert the resolution_kind returned for representative constraint, entailment, optimization, statistical, and abstention cases. |
| `EG-DECISION-ENGINE-R002` | **Evidence class recorded on every decision record.** Every decision record carries an evidence_class of proof, observation, or claim, taking the weakest premise class used in reaching the conclusion, so a pack-provided capability annotation is surfaced as a claim rather than a proof. | A negative test confirms that a capability derived only from an annotated claim is reported with evidence_class claim rather than proof. |
| `EG-DECISION-ENGINE-R003` | **Derivation records for entailed answers.** An entailment-resolved answer is backed by an is_a derivation record naming the source and premise class of each edge used, and the overall answer cannot claim proof-level evidence when it relies on an invented or unsupported ontology edge. | A negative test confirms that an answer depending on a fabricated ontology edge is refused rather than accepted as a proof. |
| `EG-DECISION-ENGINE-R004` | **Independently verifiable 0-1 integer solver certificate.** The solver in crates/eg-compute/src/solve produces a certificate naming feasibility, objective value, lower bound, optimality gap, solver version, and input digest for every solved assembly, and a separate verifier recomputes and checks that certificate independently of the solve path. | Determinism tests confirm repeated solves are byte-identical and match a committed golden certificate digest, and an exhaustive-search test confirms the solver's optimum matches brute-force search on small models. |
| `EG-DECISION-ENGINE-R005` | **Conformal and risk-controlled statistical guarantees.** Statistical heads apply acceptability-set conformal prediction, selective risk control (Learn-then-Test), and adaptive conformal inference to bound miscoverage under drift, abstaining rather than returning an uncalibrated answer when these guarantees cannot be met. | Numeric unit tests fit and evaluate each guarantee and assert the resulting coverage and abstention behavior. |
| `EG-DECISION-ENGINE-R006` | **Off-policy evaluation gated on effective sample size.** Decision evaluation records exact propensities and computes off-policy estimates using clipped or SWITCH importance sampling and doubly robust estimators, reporting effective sample size, and refuses to promote a fitted head when effective sample size falls below the configured minimum. | A unit test asserts that off-policy evaluation reports support and effective sample size and that promotion is blocked below the minimum threshold. |
| `EG-DECISION-ENGINE-R007` | **Deterministic cross-target replay of committed decision records.** A committed decision record replays to byte-identical quantized fixed-point digests using a pinned software floating-point implementation, so the same record verifies identically across the full set of supported target platforms. | A golden-vector replay test confirms identical digests on the supported targets, with the full target matrix exercised at release-qualification time. |
| `EG-DECISION-ENGINE-R008` | **Why-chosen and why-not explanations for solved assemblies.** Every solved assembly can explain why an option was chosen and, for a visible excluded option, why it was not, by performing a bounded re-solve per excluded option rather than an unbounded search. | Integration tests assert the why-not re-solve routing returns a correct, bounded explanation for excluded candidates. |
| `EG-DECISION-ENGINE-R009` | **Learned ranking stays monotone with respect to safety.** A fitted statistical head may only narrow the set of legal options or cause abstention; it can never widen the legal set or itself authorize an option that policy and hard constraints have not already permitted. | A negative test confirms that a learned head cannot override or widen the constraint-derived legal set, and that execution enforces this invariant independently of the head. |
| `EG-DECISION-ENGINE-R010` | **Typed abstention reason for unmet capability.** When no legal assembly satisfies the requested capabilities, the system returns a typed AbstainReason value naming the specific missing capability rather than a generic failure. | Unit tests assert that an unsatisfiable capability request returns an AbstainReason identifying the missing capability. |
| `EG-DECISION-ENGINE-R011` | **Work-budgeted search without an arbitrary result cap.** The solver in crates/eg-compute/src/solve/search bounds search by a deterministic node budget rather than an arbitrary cap on the number of candidate results, reporting an unresolved or certified-gap result when the budget is exhausted instead of silently truncating the option set. | Adversarial tests confirm that exhausting the budget above the accepted gap yields an unresolved result, that exhausting it within the accepted gap yields a certified gap, and that a parity case exhausts the budget without an incumbent. |
| `EG-DECISION-ENGINE-R012` | **Shared slate crediting across multiple questions.** When multiple questions are answered against the same assembly template, the system credits outcomes at the slot level across the shared template, with results aggregated consistently across the related questions. | Template-level unit tests assert slot-level crediting is applied correctly across a shared assembly template. |
| `EG-DECISION-ENGINE-R013` | **Tenant-visibility filtering before feature computation.** Decision candidates are filtered by tenant and row-level visibility before any feature is computed or counted, and no report or aggregate may expose a candidate, feature value, or statistic derived from a source outside the requesting tenant's visibility. | A negative test confirms that a candidate from another tenant is excluded from decision results and aggregates. |
| `EG-DECISION-ENGINE-R014` | **Composition solved as bounded constraint optimization.** Agent or component composition is resolved by lowering covering, implication, exactly-one, knapsack, feature-compatibility, and cardinality requirements into a bounded 0-1 integer program and solving it exactly, rather than by a single unverified model-generated choice. | Exhaustive-search and model-validation tests confirm the lowered constraint model produces correct, verifiable compositions across representative cases. |
| `EG-DECISION-ENGINE-R015` | **No generative model weights inside the decision engine.** The decision engine contains no large language model weights and performs no free-text generation; its statistical heads are small fitted models used only to rank legal options or abstain. | Architecture and dependency review confirms no generative model weights or text-generation calls are present in the decision engine's code paths. |
| `EG-DECISION-ENGINE-R016` | **Training restricted to independently evaluated outcomes.** Calibration and training data include only outcomes recorded with exact propensities by approved commit principals; a self-reported or language-model-resolved outcome is excluded from the calibration or training set. | Unit tests confirm that every planted defective label is refused by name and that a language-model-resolved abstention never enters the calibration set. |
| `EG-DECISION-ENGINE-R017` | **Single write authority per durable decision state kind.** Each kind of durable decision state, such as an assembled agent graph, a graph mutation batch, or a published component with its receipt, has exactly one write authority responsible for committing it, so no second code path can independently mutate that state. | Integration tests confirm that only the designated write path can commit each kind of durable decision state and that a bypassing attempt is rejected. |
| `EG-DECISION-ENGINE-R018` | **Unknown facts never default to zero in the solver.** When a cost, latency, or capability fact needed by the solver objective is unknown, the solver treats it as unknown rather than silently substituting zero or a true or false default, and surfaces the gap instead of producing a misleadingly optimal result. | A unit test confirms that an unknown required fact prevents a false-confidence solve rather than being silently defaulted. |
| `EG-DECISION-ENGINE-R019` | **Decision commit re-derives and verifies before writing.** Committing a decision result re-derives the result, verifies its certificate, checks every pinned component revision, and compares the candidate-universe catalog digest with a compare-and-set, all within one transaction, so a stale catalog or fabricated input fails closed instead of being committed. | Integration tests confirm that a stale catalog or a fabricated input is rejected at commit time while a byte-identical retry commits idempotently. |
| `EG-DECISION-ENGINE-R020` | **Bounded, keyed exploration excluded from sensitive questions.** Exploratory ranking requires an explicit budget and an unpredictable HMAC-keyed seed, and is unavailable for security, policy, write-back, and irreversible-action questions regardless of the requested budget. | Unit tests verify the keyed seed against a published HMAC test vector and confirm that exploration on a security question is refused by the served path. |
| `EG-DECISION-ENGINE-R021` | **Versioned feature schema for decision candidates.** Decision ranking computes a versioned feature set over caller-visible candidates, including vector similarity, candidate-local BM25, entailed coverage, provenance quality, belief confidence, cost and latency, freshness, and outcome statistics, so a feature schema change can be tracked and replayed. | Unit and client tests assert the versioned feature vector is computed correctly for representative candidates. |
| `EG-DECISION-ENGINE-R022` | **Separation of full-label and bandit-label training regimes.** Training data distinguishes gold-labelled questions, which provide a full label, from executed-option-only outcomes, which provide a bandit label, and each regime is admitted into fitting only through its own path. | Unit tests in the admission path confirm gold-labelled and bandit-labelled data are routed and validated separately. |
| `EG-DECISION-ENGINE-R023` | **Hierarchical pooling of outcome statistics with a minimum-sample gate.** Outcome statistics are pooled hierarchically by kind, capability class, and option using a Beta-Binomial model, and a pool below its configured minimum sample size cannot support promotion of a fitted head. | A unit test confirms that insufficient pooled support for an option blocks promotion. |
| `EG-DECISION-ENGINE-R024` | **Multi-class and binary calibration utilities.** Decision confidence is calibrated using temperature, vector, or Dirichlet scaling for multi-class outputs, and isotonic calibration only for the binary entity-resolution case, with the calibration method recorded on the resulting receipt. | A unit test confirms pooled calibration output is recorded on the fit receipt. |
| `EG-DECISION-ENGINE-R025` | **Drift detection via out-of-distribution checks and adaptive conformal bounds.** The decision engine detects drift by checking incoming features for out-of-distribution values and by bounding miscoverage with adaptive conformal inference, abstaining rather than ranking when drift is detected. | A unit test confirms that an out-of-distribution feature causes the head to abstain. |
| `EG-DECISION-ENGINE-R026` | **Inverse-probability-weighted audit sampling of acted decisions.** A sample of acted decisions is selected for audit using inverse-probability weighting at a fixed five-percent rate, and every audited decision record carries an audit flag usable by downstream calibration. | Unit tests assert that evaluated records carry the audit flag and that calibration correctly applies the inverse-probability weighting. |
| `EG-DECISION-ENGINE-R027` | **WeightedFeatures and ListwiseLogistic fitted decision heads.** The decision engine supports a WeightedFeatures head, which is advisory only and never calibrated, and a ListwiseLogistic head, which is a deterministic, bit-for-bit reproducible optimizer; a further Kolmogorov-Arnold listwise head is not yet included. | Unit tests confirm a fit is bit-for-bit reproducible and certifies an act threshold, and that the WeightedFeatures head remains advisory and is never calibrated. |
| `EG-DECISION-ENGINE-R028` | **Natural-language template routing without a generative model.** A natural-language decision request is routed to a matching NlTemplate using candidate-local BM25, embedding, or ontology-label similarity rather than a generative model call. | Unit tests cover natural-language template matching; end-to-end served routing is proven when the serving path is exercised. |
| `EG-DECISION-ENGINE-R029` | **Decision-based retrieval-plan selection.** The decision ladder selects among retrieval plans, such as LeanRAG, reciprocal-rank fusion, or direct SPARQL querying, for a given request using the same typed decision mechanism as other question families. | An integration test asserts the correct retrieval plan is selected for representative request shapes. |
| `EG-DECISION-ENGINE-R030` | **Decision-based ingestion path routing.** Ingestion requests are routed to a fast, medium, or slow processing path through the same typed decision mechanism used for other question families, rather than a hard-coded rule. | An integration test confirms ingestion routing selects the expected path for representative inputs. |
| `EG-DECISION-ENGINE-R031` | **Expected-value scheduling for enrichment work.** Enrichment scheduling selects candidate work by comparing expected value against cost through the typed decision mechanism, rather than a fixed priority order. | An integration test confirms enrichment scheduling selects the higher expected-value option under representative cost scenarios. |
| `EG-DECISION-ENGINE-R032` | **Entity-resolution candidates with conformal guarantees.** Entity-resolution (owl:sameAs) candidate decisions use the binary entity-matching head with isotonic calibration and report a conformal guarantee validated against a gold label set, abstaining when that guarantee cannot be met. | A unit test against a gold-labelled set confirms the reported conformal guarantee holds and that insufficient confidence results in abstention. |
| `EG-DECISION-ENGINE-R033` | **Decision-based schema mapping for SQL sources.** Mapping a source column to an ontology property for SQL ingestion and pack content is resolved through the typed decision mechanism, producing a proposed mapping with its evidence class rather than an unverified direct assignment. | An integration test confirms a representative column set maps to the expected ontology properties with correct evidence classification. |
| `EG-DECISION-ENGINE-R034` | **Proposal-only contradiction-handling suggestions.** When the truth-maintenance system detects a contradiction, the decision engine may propose a resolution but never performs an automatic retraction; any retraction requires a separate, explicit authorization step. | A negative test confirms that a detected contradiction produces a proposal only and that no automatic retraction occurs. |
| `EG-DECISION-ENGINE-R035` | **Decision-based routing for execution configuration.** This repository's graph.decide() method accepts requests to select among candidate models, prompts, skills, tools, harness modes, account modes, or sandbox configurations and returns a ranked or constrained choice with its evidence class; the consuming execution environment applies that choice. | A contract test confirms graph.decide() returns a valid typed choice and evidence class for each supported routing category. |
| `EG-DECISION-ENGINE-R036` | **graph.assemble() as the authority for agent composition.** graph.assemble() is the sole method for composing an agent graph from typed tasks and capabilities, replacing a model-generated composition choice with a verifiable constraint-solved result. | An integration test confirms graph.assemble() produces a legal, certificate-backed agent graph for representative composition requests. |
| `EG-DECISION-ENGINE-R037` | **Escalated abstentions re-enter as claims.** When a typed abstention is escalated to a language model or a human reviewer and a resolution is produced, that resolution re-enters the decision engine only as a claim-class input, never as a proof or observation. | A negative test confirms a resolution produced by escalation is recorded with evidence_class claim. |
| `EG-DECISION-ENGINE-R038` | **Advisory pre-tool risk scoring.** Before a tool invocation, the decision engine can return an advisory risk score for the candidate action; the score informs but never itself authorizes or blocks execution. | A unit test confirms the risk score is returned as advisory and does not gate execution on its own. |
| `EG-DECISION-ENGINE-R039` | **Cost-aware routing using accounting data.** Routing decisions incorporate cost information sourced from the usage and cost accounting subsystem, preferring lower-cost legal options when they satisfy the same constraints. | An integration test confirms a routing decision prefers the lower-cost legal option when accounting data distinguishes candidates. |
| `EG-DECISION-ENGINE-R040` | **Guarded promotion of fitted heads via publish receipt.** A fitted decision head is promoted to active use only through the component-publish path gated on a matching DecisionEval receipt; a receipt that does not match the evaluated digest causes promotion to be refused. | Unit tests confirm a mismatched receipt is refused with an evaluation-receipt-mismatch error while a matching receipt allows publish. |
| `EG-DECISION-ENGINE-R041` | **Connector event triage through Decide.** EG classifies inbound connector events by routing them through the decision ladder in evaluate-only mode, returning a proposal and its evidence class without taking any action on the connector's behalf. A sampled subset of these evaluations is logged for audit. | An integration test submits synthetic connector events, calls the evaluate-only triage path, and asserts no side effect occurs while a sampled fraction of evaluations is recorded. |
| `EG-DECISION-ENGINE-R042` | **Connector tool-choice advisory via Decide.** Decide evaluates which internal tool a connector should use for a given task and returns a proposal with evidence only; the connector's own deterministic authorization path, not Decide, governs whether any resulting write-back actually occurs. | A test exercises tool-choice evaluation for a connector task and confirms the proposal alone cannot trigger a write-back without passing the separate deterministic authorization check. |
| `EG-DECISION-ENGINE-R043` | **Write-back proposals routed through Decide.** EG's decision ladder can produce a write-back proposal with supporting evidence for a connector action, but the proposal never authorizes the write itself. Any exploration or statistical head used to generate the proposal stays outside the deterministic authorization step that must separately approve the write. | A negative test asserts a Decide-sourced write-back proposal has no external effect until it passes the connector's own deterministic authorization check. |
| `EG-DECISION-ENGINE-R044` | **A2A task routing through the decision ladder.** Inbound A2A tasks are routed to an existing or assembled agent graph by applying the same typed decision ladder used for other question families, returning a routing resolution with its resolution kind and evidence class rather than an unexplained match. | An integration test submits inbound A2A tasks and asserts each is routed to a graph through a recorded decision with a resolution kind and evidence class. |
| `EG-DECISION-ENGINE-R045` | **Smallest covering tool subset within a context budget.** Decide selects the smallest tool subset that still covers every required capability within a caller-specified context budget, so a multiplexer can expose fewer tools to a caller without losing coverage. | A test constructs a capability requirement set with a token budget and asserts the returned subset is minimal, covers every required capability, and stays within budget. |
| `EG-DECISION-ENGINE-R045.1` | **Typed tool-subset request and greedy covering-set selection.** EG defines a typed tool-subset request body and a greedy set-cover selection over it, with no server or candidate-source dependency. | Unit tests assert the selection is minimal, covers every required capability, and refuses when coverage or budget cannot be met. |
| `EG-DECISION-ENGINE-R045.2` | **Tool-subset selection wired into Decide.** EG wires the R045.1 selection into a dedicated Decide question kind, reading tool candidates from the agent library and returning the selected subset on the served decision record. | A served test submits a tool-subset question and asserts the returned record's selected subset is minimal, covers every required capability, and stays within the caller's budget. |
