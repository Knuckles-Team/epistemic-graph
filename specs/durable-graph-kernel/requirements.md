# EG-DURABLE-KERNEL requirements

| ID | Requirement | Verification |
|---|---|---|
| `EG-DURABLE-KERNEL-R001` | **Outbox head-only attempt accounting and rewind.** The outbox increments retry attempts only for the row currently at the head of a stream, so a failing head cannot exhaust the attempt budget of healthy successor rows. A consumer can declare an explicit reject, which dead-letters the head immediately and reports the transition. An administrator can list head status and dead letters. The administrator can also issue a rewind to replay from an earlier position. | Outbox tests prove three behaviours. A failing head never dead-letters a healthy successor, and repeated head releases dead-letter only the head. A consumer reject dead-letters immediately, and rewind replays. |
| `EG-DURABLE-KERNEL-R002` | **Outbox consumers get per-class topics and reject-driven rebuild.** Outbox consumers publish to semantically distinct topics per message class. A reasoning-projection consumer that rejects a message triggers a rebuild rather than silently acknowledging a skipped projection. `MutationOutbox` exposes an administrative method for inspecting and managing consumer state. The outbox reports metrics on attempts, rejects, dead letters, and rebuilds. | Verified by outbox integration tests asserting per-class topic routing, reject-triggered rebuild of a reasoning projection, and exported outbox metrics. |
| `EG-DURABLE-KERNEL-R003` | **Owner-store layout lineage registry with typed upgrade refusal.** The owner-store layout maintains a lineage registry that recognizes every supported on-disk format and refuses an unsupported layout with a named `{LAYOUT}_FORMAT_UPGRADE_REQUIRED` error rather than reinterpreting it silently. A generated document records the steps required to remove a retired layout from the registry. | Verified by a golden lineage test that loads each supported manifest format and checks the typed refusal for unsupported ones. |
| `EG-DURABLE-KERNEL-R004` | **Outbox attempt accounting is scoped to the head row.** Re-leasing an outbox row increments the attempt count only for the row at the head of its stream. Healthy successor rows staged behind it never gain an attempt. A failing head cannot dead-letter its successors. This accounting is implemented in `crates/eg-transaction/src/outbox/claim.rs`. | One test asserts a failing head never dead-letters a healthy successor. Another test asserts sixteen re-leases of the head dead-letter only the head. |
| `EG-DURABLE-KERNEL-R005` | **Outbox delivery state remains local to the owning node.** The local store owner writes outbox delivery-side rows. The multi-group raft layer does not replicate them. Delivery progress stays node-local and outside the replicated log. | Confirmed by an integration test checking that outbox delivery rows are not present in replicated state on non-owning cluster members. |
| `EG-DURABLE-KERNEL-R006` | **Engine startup does not block on one store's lazy open.** Engine startup must not refuse entirely when the agent-library store fails to open. That store opens lazily. A failure to open it affects only the operations that depend on it, not overall startup. | A startup test forces the agent-library store to fail its open. The test asserts that the engine still starts and serves unrelated operations. |
| `EG-DURABLE-KERNEL-R006.1` | **A clean reopen writes nothing, and a fresh shard is ready in one commit.** Open proves an already-bound serving scope in a read transaction. It begins no write transaction for that proof. The bind refuses a read-only open before that proof, because a bound scope is write authority. Ledger bootstrap checks the declared ledger tables under a write capability, then aborts. It commits nothing and issues no fsync. A fresh owner file binds its control scope inside the one create commit. Create, bind and ledger bootstrap therefore cost one commit. The engine opens the three sidecar stores beside the graph shards. They are `admin-mutations.redb`, `node_info.redb` and `cluster_hierarchy.redb`. A refused open removes every sidecar file that attempt created. | Storage-kernel tests reopen a bound store and assert the file bytes stay unchanged after the bind. A create-bound store reports its scope bound without a second commit. A K=8 backend test asserts every sidecar file exists after open. A second test refuses a shard open and asserts no new sidecar file remains. |
| `EG-DURABLE-KERNEL-R006.2` | **Startup open has a time budget that holds under host load, and each open is diagnosable.** The budget runs in one process on a real disk, beside 16 fsync-writing threads and 32 CPU-burn threads. Under that load a fresh K=8 store opens within 4 s. A small reopened K=8 store opens within 2 s. A populated reopen of about 300 MB on its markers opens within 2.5 s. A separate stress check runs ten copies in parallel, each with its own load. Its looser limits are 60 s fresh and 45 s for each reopen. Every kernel-owned store open logs one line with its duration and phase split. The phases are file open, table validation, recovery scan or skip, bind and ledger. The same split feeds the `epistemic_graph_store_open_phase_seconds` histogram. The `epistemic_graph_store_open_recovery_scan_total` counter records the scan outcome. | `tests/shard_open_budget.rs` builds the fresh, small and populated K=8 stores under that load. It asserts each budget from the open call's own wall clock. It also removes the markers and reopens, to show the full-scan fallback still opens the store. A missed limit prints the captured per-store phase lines. The build host runs the gate ten times in a row with no failure. The ignored stress test runs the ten parallel copies. |
| `EG-DURABLE-KERNEL-R006.3` | **A clean-shutdown marker lets open skip the full recovery scan.** A graceful close writes a marker file beside the owner file. The marker binds the store incarnation and the physical identity. It also binds the file length, the modification time and the redb header page. That header page carries the last commit. Open skips the row scan of `validate_recovery_content` only when the marker matches the file. A skipped open still checks the persisted root, every scope binding and version row, and every fence's stamped identity. The marker vouches only for content that passed the scan. A session may create the file or commit a write. Its close then re-runs the scan read-only. The close writes the marker only when that scan passes. redb rewrites the header when it opens a file for write. A writable open that found a valid marker therefore stamps it again against that header. The first commit after an open durably removes the marker before redb's commit starts. No commit can become durable while a marker exists. A crash after any commit therefore leaves no valid marker. An aborted write commits nothing, so it leaves the marker in place. The ledger bootstrap on every open is such a write. An absent, torn, copied, restored, upgraded or externally rewritten file runs the full scan. The marker speeds up startup and proves no integrity. Rows tampered with behind a valid marker are out of scope. | Storage-kernel tests cover each case. A clean reopen reports the scan skipped. A missing marker, a torn marker, a copied marker and an external commit each run the scan. Beginning a write keeps the marker. The commit removes it, and the next close restores it. An aborted write keeps a valid marker. An aborted ledger bootstrap keeps it, and the next open still skips the scan. A child process killed by `abort()` after a write leaves no marker, so the reopen scans. A child killed without writing keeps its still-true marker. A store closed with a foreign fence writes no marker. A forged matching marker still lets the fence check refuse the reopen. |
| `EG-DURABLE-KERNEL-R006.4` | **Pre-listener boot does not block on write-lock-holding maintenance.** The projection drain never holds the global write lock across the agent-library store open. The worker ensures the store outside the lock. Publishing the ensured handle takes one short write. A re-check lets a concurrent ensurer win. Per-row critical sections stay short. No write spans a projection graph commit. Each non-empty sweep logs one INFO line: rows claimed, graphs committed, elapsed. The worker never performs minutes of work silently. The matview reload and the ts reconciliation close RAM re-hydration and crash-window residuals. Nothing requires them to precede serving. They run as background tasks spawned after the primary listeners bind. Each logs its start and completion: counts and elapsed. Code roots: `src/server/connector_pack_projection.rs`, `src/server/boot_maintenance.rs`, `src/server/transport.rs`, `src/server_startup.rs`, `src/main.rs`. | The test seeds N pending import rows on a temp durable store. It boots the real wiring: projection worker, UDS listener, post-bind maintenance. It asserts the listener binds within 30s and before the drain completes. It asserts the drain finishes within a bounded wait. |
