# EG-BRANCH-MERGE requirements

| ID | Requirement | Verification |
|---|---|---|
| `EG-BRANCH-MERGE-R001` | **Typed branch model and CreateBranch.** Subsystem: ingest, branches. Entry: new `Method::CreateBranch { tenant, graph, name, base_engine_version }` in `crates/eg-types/src/protocol/method/method_11.rs`. Caller: request boundary → `src/server/dispatch/graph_pipeline/native_routes.rs` → `src/server/handlers/branch.rs::handle_create_branch` → `BranchRegistry::create`. Types in `crates/eg-types/src/branch.rs`: `Branch { tenant, graph, name, base_version: u64, head_commit: String, created_by, created_at, deleted: bool }` and `BranchRef { tenant, graph, name }`. A branch is a registry row. It copies no graph data. The registry lives in `src/redb_store/branch_registry.rs` (new) under the owner-store lineage (EG-DURABLE-KERNEL-R003). Rule: `base_engine_version` defaults to the graph head. The name matches `[a-z0-9][a-z0-9._/-]{0,127}`. The name `main` and the prefix `eg/` are reserved. Refusals: `BRANCH_NAME_INVALID`, `BRANCH_EXISTS`, `BRANCH_NAME_RESERVED`, `BRANCH_TENANT_DENIED`, `BRANCH_BASE_UNKNOWN`. Each refusal occurs before any registry write. Writes: one registry row through the commit and raft path. Depends on: EG-DURABLE-KERNEL-R003, EG-DURABLE-KERNEL-R019. | Test: `tests/test_branch_create.py::test_branch_create_and_refusals` (L4) creates a branch and reads it back. Each of five refusals returns its code and leaves no registry row. |
| `EG-BRANCH-MERGE-R002` | **Branch-scoped mutations on one commit chain.** Subsystem: ingest, branches. Entry: any served mutation. Caller: `src/server/dispatch/graph_pipeline/gateway.rs` → `branch::resolve_target`. `MutationBatch` (`crates/eg-types/src/mutation_batch/model/batch.rs`) gains `branch: Option<String>`; the default is `main`. Each commit appends a `BranchCommit { id, branch, parents, engine_version, manifest_digest, actor, created_at }` (`crates/eg-types/src/branch.rs`) with the prior head as parent. This is the single commit chain. A source changeset (EG-SCM-R002) is the payload of the branch commit that carries it. No second chain exists. Branch writes stay invisible to `main` and sibling branches until merge. Idempotency key: `(tenant, graph, branch, idempotency_key)` following EG-DURABLE-KERNEL-R019. A replay returns the original receipt. The receipt gains `branch_head`. Refusals: `BRANCH_UNKNOWN`, `BRANCH_DELETED`, `BRANCH_TENANT_DENIED`, all before any graph change. Writes: commit-before-ack through the existing commit and raft path. Depends on: EG-BRANCH-MERGE-R001, EG-DURABLE-KERNEL-R009, EG-DURABLE-KERNEL-R019. | Test: `tests/test_branch_scoped_mutation.py::test_branch_write_invisible_until_merge` (L4) writes on a branch and asserts `main` is unchanged. It asserts the replayed receipt is identical. |
| `EG-BRANCH-MERGE-R003` | **Merge base and fast-forward.** Subsystem: ingest, branches. Entry: new `Method::BranchMerge { tenant, graph, source, target, merge_base }`. Caller: `src/server/handlers/branch.rs::handle_branch_merge` → `crates/eg-types/src/branch.rs::merge_base` and `classify`. Outcome set: `up_to_date`, `fast_forward`, `merged`, `conflict` (enum `MergeOutcome`). Merge base is the lowest common ancestor on the commit DAG chosen by highest generation number. A tie goes to the lexicographically smallest commit id. `up_to_date`: the source head is an ancestor of the target head. `fast_forward`: the target head is an ancestor of the source head. The handler moves the target to the source head without an entity scan. The receipt names the source head as merged parent. Refusal: `BRANCH_NO_COMMON_ANCESTOR`, typed, never an implicit base. Writes: `fast_forward` writes one pointer move through the commit path. `up_to_date` writes nothing. Depends on: EG-BRANCH-MERGE-R002. | Test: `tests/test_branch_merge_base.py::test_merge_outcomes_up_to_date_and_fast_forward` (L4) drives four topologies: linear, diamond, disjoint and equal heads. It asserts the closed outcome set and the diamond merge base. |
| `EG-BRANCH-MERGE-R004` | **Entity-level three-way merge.** Subsystem: ingest, branches. Caller: `handle_branch_merge` → `src/server/handlers/branch/merge.rs::merge_entities` (new) when the outcome is neither `up_to_date` nor `fast_forward`. Identity: node `(tenant, type, key)`; edge `(source, target, relation_type)` (EG-REPO-INGEST-R009.1). For each entity compare base, source and target versions. Unchanged on both sides stays on the target without row copy. Changed on one side is adopted. Changed on both sides becomes a `ConflictRecord` (R005). An adopted entity passes schema, constraint and ABox validation through the authorities of EG-DECISION-ENGINE-R102.1. A failure refuses the whole merge with `MERGE_ADOPTION_INVALID{entity}` and publishes nothing. File-level line merge for source files is the separate row `EG-BRANCH-MERGE-R010`. Writes: none until R007 publishes the atomic result. Depends on: EG-BRANCH-MERGE-R003, EG-DECISION-ENGINE-R102.1. | Test: `tests/test_branch_three_way_merge.py::test_entity_level_outcomes` (L4) drives disjoint, one-sided and both-sided fixtures. It asserts the published target state and that the invalid adoption publishes nothing. |
| `EG-BRANCH-MERGE-R005` | **Epistemic conflict resolution.** Subsystem: ingest, branches. Caller: `merge_entities` (R004) → `src/server/handlers/branch/conflict.rs::resolve` → `Decide` with `QuestionKind::ResolveConflict` (EG-DECISION-ENGINE-R828). Record: `ConflictRecord { entity, candidate_a, candidate_b, state: open or resolved, policy_digest }` in `crates/eg-types/src/branch.rs`. Each candidate keeps bitemporal windows (`valid_from`, `valid_until`, `tx_from`, `tx_until`) and provenance (source reliability, confidence, evidence refs). The decision picks the winner or abstains. On abstention the entity stays unmerged and the conflict stays open. The open conflict is queryable through `WITH KNOWLEDGE`. A resolved row keeps a contradiction link and both evidence refs. Resolution is never last-write-wins. Refusals: `CONFLICT_POLICY_MISSING`, `CONFLICT_EVIDENCE_STALE`, `CONFLICT_NONFINITE` (registered in EG-DECISION-ENGINE-R828). Writes: conflict records and resolutions are written by the merge publication of R007, not by `Decide`. Depends on: EG-BRANCH-MERGE-R004, EG-DECISION-ENGINE-R828. | Test: `tests/test_branch_epistemic_conflict.py::test_evidence_weighted_resolution_and_open_conflict` (L4) resolves under a pinned policy, re-runs without a policy, and reads the open conflict with both candidates. |
| `EG-BRANCH-MERGE-R006` | **Branch diff and time-travel reads.** Subsystem: ingest, branches. This row owns the transaction, commit and diff vocabulary that EG-DURABLE-KERNEL-R609.1 named: `KgTransaction`, `KgCommit` and `KgDiff` in `crates/eg-types/src/versioning.rs`. Entry: new `Method::BranchDiff { tenant, graph, from, to }` and `Method::BranchReadAt { tenant, graph, branch, engine_version }`. Caller: `src/server/handlers/branch.rs::handle_branch_diff` and `handle_branch_read_at`. The as-of read pins the off-lock snapshot (EG-DURABLE-KERNEL-R023) to the engine version on the branch chain. It applies the tenant filter of EG-DURABLE-KERNEL-R029. The diff is a typed change feed built from `ChangeEnvelope` records (`crates/eg-types/src/change_envelope.rs`). It lists added, updated and deleted entities against the baseline (entity, operation, image ref). Diff output is bounded by page size 1,000 (config key `branch.diff_page_size`, bounds [1, 10000]). Refusals: `BRANCH_VERSION_NOT_ON_CHAIN`, `BRANCH_TENANT_DENIED`. Writes: none. Depends on: EG-BRANCH-MERGE-R002, EG-DURABLE-KERNEL-R023, EG-DURABLE-KERNEL-R029. | Test: `tests/test_branch_time_travel.py::test_as_of_reads_and_diff` (L4) walks a three-version chain. It reads each version and asserts the diff equals the intervening commits. |
| `EG-BRANCH-MERGE-R007` | **Atomic merge publication.** Subsystem: ingest, branches. Caller: `handle_branch_merge` → `src/server/handlers/branch/publish.rs::publish_merge` (new). It reuses the cross-modal transaction and raft sealing of EG-DURABLE-KERNEL-R009. The receipt is the `BranchCommit` record with two parents. It carries commit id, manifest digest, parents, actor and created_at. Replay key: `(source_head, target_head, merge_base)`. A replay returns the original receipt. A merge that cannot complete publishes nothing and never claims a rollback. Refusals: `MERGE_TARGET_STALE` when the target head moved past the recorded head, never a silent rebase. `MERGE_ACTOR_UNKNOWN` for an unknown actor. Writes: one atomic publication across every affected type and modality. Depends on: EG-BRANCH-MERGE-R004, EG-BRANCH-MERGE-R005, EG-DURABLE-KERNEL-R009. | Test: `tests/test_branch_merge_publish.py::test_atomic_two_parent_publication_and_replay` (L4) publishes a two-parent merge, reads it back byte-identically and replays it. The stale-target case leaves the target unchanged. |
| `EG-BRANCH-MERGE-R008` | **Line-level three-way merge for file blobs.** New `crates/eg-compute/src/line_merge.rs::merge_lines(base, ours, theirs) -> LineMerge{Clean(bytes), Conflict(hunks)}`. It runs a diff3 on lines separated by `\n`. Binary blobs never merge: any overlap is a conflict. Caller: `source_changeset.rs::accept`. Depends on: `EG-BRANCH-MERGE-R004`. | Test: `crates/eg-compute/tests/line_merge.rs::clean_and_conflicting_hunks` (L2) and the served test of `EG-SCM-R003` (L3). |
| `EG-BRANCH-MERGE-R009` | **Landing policy check at merge publish.** The merge publish step into a protected branch calls `landing_policy::check(repo, branch, head)`. It refuses with `LANDING_GATE_BLOCKED` when a required gate has no passing verdict. The verdict must match the head tree digest. Depends on: `EG-SCM-R008`. | Test: a served merge test with one failing gate asserts the refusal and an unchanged target head (L3). |
| `EG-BRANCH-MERGE-R010` | **Line-granularity file merge for source changesets.** Subsystem: ingest, source control. Caller: `EG-SCM-R003` overlap path → `src/server/handlers/branch/line_merge.rs::merge_file` (new). Rule: a three-way text merge over base, source and target blob bytes. Hunks that touch disjoint line ranges merge. Hunks that touch overlapping ranges produce `SOURCE_CONFLICT{paths}`. The merge is deterministic and pure. A binary blob never merges and conflicts. Refusals: `SOURCE_CONFLICT`, `MERGE_BLOB_UNREADABLE`. Writes: none; the caller lands the merged blob through the accept path. Depends on: EG-BRANCH-MERGE-R004, EG-SCM-R001, EG-SCM-R003. | Test: `tests/test_branch_line_merge.py::test_disjoint_hunks_merge_and_overlap_conflicts` (L4) merges two edits to disjoint lines and conflicts on one shared line. |
