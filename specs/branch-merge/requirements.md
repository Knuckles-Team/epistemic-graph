# EG-BRANCH-MERGE requirements

| ID | Requirement | Verification |
|---|---|---|
| `EG-BRANCH-MERGE-R001` | **Typed branch model and create.** Model: a branch is a registry entry. It binds tenant, graph, name, base engine version, and creator. A branch is a view over the commit chain. It is not a data copy. Behavior: CreateBranch registers the name at its base version. It returns the branch identity. Branch reads use the off-lock graph snapshot. Tenant RLS applies as usual. Wiring: add a branch module to `crates/eg-types`. Serve it through the request boundary. Persist registrations in the owner-store lineage registry (EG-DURABLE-KERNEL-R003). Refusal: the registry refuses empty or duplicate names. It refuses reserved-namespace names. It refuses foreign-tenant creation. It refuses an unresolvable base version. Every refusal is a typed error before state change. Evidence: the identity round-trips. Every refusal leaves no registry entry. | `tests/test_branch_create.py::test_branch_create_and_refusals` creates a branch. It reads the branch back. Each refusal returns a typed error with no registry entry. |
| `EG-BRANCH-MERGE-R002` | **Branch-scoped mutations.** Model: a mutation names its target branch. A commit appends to that branch's append-only chain. The commit carries a parent pointer to the branch's prior head. It commits commit-before-ack. Behavior: branch writes show on that branch only. They stay invisible to main and sibling branches until merge. Branch writes are idempotent under a tenant-scoped branch idempotency key. Wiring: extend the mutation path in `src/server/handlers` with branch targeting. Reuse the existing commit and raft paths. Reuse the tenant-scoped idempotency pattern of EG-DURABLE-KERNEL-R019. Refusal: the engine refuses a mutation that names an unknown branch. It refuses a deleted branch. It refuses a foreign-tenant branch. The refusal happens before any graph mutation. A replayed branch write returns the original receipt. Evidence: a branch write is invisible on main until merge. The replay returns an identical receipt. | `tests/test_branch_scoped_mutation.py::test_branch_write_invisible_until_merge` writes on a branch. It asserts main is unchanged. It asserts the replay receipt is identical. |
| `EG-BRANCH-MERGE-R003` | **Merge base and fast-forward.** Model: merge outcomes form the closed set `up_to_date` / `fast_forward` / `merged` / `conflict`. The engine computes them over the two branch commit chains. Behavior: when the target has no writes since the merge base, the merge fast-forwards. When the source head is a descendant of the target head, the merge fast-forwards. The fast-forward moves the target to the source head without an entity scan. When the source is already contained, the outcome is up-to-date. Nothing publishes. Wiring: add merge-base computation to the branch module. Reuse the commit-chain walk of the owner store. Refusal: the engine refuses a merge whose branches share no ancestor. The refusal is typed. It never invents an implicit base. Evidence: up-to-date publishes nothing. Fast-forward advances the target with a single-parent receipt. The receipt names the source head as merged parent. | `tests/test_branch_merge_base.py::test_merge_outcomes_up_to_date_and_fast_forward` drives four fixture topologies. It asserts the closed outcome set. |
| `EG-BRANCH-MERGE-R004` | **Entity-level three-way merge.** Model: the merge resolves per entity. Node identity is `(tenant, type, key)`. Edge identity is the existing `(source, target, relation_type)` triple (EG-REPO-INGEST-R009.1). Behavior: both-sides-unchanged entities stay on the target without row copy. One-sided entities are adopted. Adoption passes schema, constraint, and ABox validation. The validation uses the existing typed authorities. Both-sides entities become typed conflicts. They are never silent overwrites. Wiring: add the entity-level merge pass to the branch module. Reuse the constraint and ABox check authorities of schema repair (EG-DECISION-ENGINE-R102.1). Refusal: an adopted entity that fails validation refuses the whole merge. The merge refuses atomically with a named reason. No partial merge publishes. Evidence: disjoint, one-sided, and both-sides fixtures each produce the declared outcome. The atomic-refusal case publishes nothing. | `tests/test_branch_three_way_merge.py::test_entity_level_outcomes` drives the three fixtures. It asserts the published target state matches the expected entities exactly. |
| `EG-BRANCH-MERGE-R005` | **Epistemic conflict resolution.** Model: a conflicted entity produces a typed conflict record. The record carries both candidate values. Each candidate keeps its bitemporal windows (`valid_from`/`valid_until`, `tx_from`/`tx_until`). Each keeps its provenance (source reliability, confidence, evidence refs). Behavior: an owner-pinned epistemic policy selects the winner. Or it leaves the conflict open. The open conflict is a typed queryable state. Resolution is never a silent last-write-wins. A resolved row keeps the contradiction link. It keeps both evidence refs in its epistemic neighbourhood. Wiring: extend the conflict path of R004. Reuse the epistemic neighbourhood fields served by `WITH KNOWLEDGE`. Reuse the source-reliability authority. Refusal: the engine refuses resolution with a missing epistemic policy. It refuses stale evidence refs. It refuses nonfinite confidence. A conflict with no policy leaves the entity unmerged. The engine never guesses. Evidence: the two-candidate fixture resolves per the pinned policy. The no-policy conflict stays open with both candidates queryable. Stated advantage: the comparator's merge is entity-level last-write-wins with constraint checks. This row is evidence-weighted and validity-aware. | `tests/test_branch_epistemic_conflict.py::test_evidence_weighted_resolution_and_open_conflict` resolves under a pinned policy. It re-runs without a policy. It reads back the open conflict with both candidates. |
| `EG-BRANCH-MERGE-R006` | **Branch diff and time-travel reads.** Model: a branch or commit diff is a typed change feed. It names a baseline (entity, operation, image ref). It uses the engine's change-envelope vocabulary. A branch reads at any engine version on its chain. Behavior: an as-of-version read serves the off-lock snapshot. The snapshot pins to that version. It stays RLS-filtered. The diff between two versions lists added, updated, and deleted entities. Wiring: add as-of snapshot reads to the branch module. Reuse the existing snapshot and off-lock read paths. Reuse the tenant-scoping filter (EG-DURABLE-KERNEL-R029). Refusal: the engine refuses a version not on the branch's chain. It refuses a cross-tenant diff. Both refusals are typed. Evidence: a read at version N equals the write set at N. The diff between N and M equals the commits in between. The foreign-tenant and unknown-version cases refuse. | `tests/test_branch_time_travel.py::test_as_of_reads_and_diff` walks a branch chain of three versions. It reads each as-of. It asserts the diff matches the intervening commits. |
| `EG-BRANCH-MERGE-R007` | **Atomic merge publication.** Model: a merge publishes the target change atomically. The publication spans every affected type and modality. It uses the existing cross-modal transaction and raft path. The receipt is a typed two-parent commit. The receipt carries commit id, manifest digest, parents, actor, and creation timestamp. Behavior: replay against the same `(source_head, target_head, merge_base)` returns the original receipt. A merge that cannot complete publishes nothing. It never claims a rollback. Wiring: extend the commit publication path. Reuse raft command sealing (EG-DURABLE-KERNEL-R009). Reuse the cross-modal transaction. Refusal: the engine refuses a target that advanced past its recorded head. The refusal names the state as stale. It never silently rebases. It refuses an unknown actor. Evidence: the two-parent receipt reads back byte-identically. The replay returns the same receipt. The stale-target case publishes nothing. | `tests/test_branch_merge_publish.py::test_atomic_two_parent_publication_and_replay` publishes a two-parent merge. It reads it back. It replays it. It asserts the stale-target refusal leaves the target unchanged. |
