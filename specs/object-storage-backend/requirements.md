# EG-OBJECT-STORAGE-BACKEND requirements

| ID | Requirement | Verification |
|---|---|---|
| `EG-OBJECT-STORAGE-BACKEND-R001` | **Typed object-store backend specification.** Model: a `StorageBackendSpec` declares the durable-store backend for a graph. Two variants exist. `local` is redb and is the default. `object-store` is S3-compatible. The spec names endpoint, bucket, and root by secret reference only. It declares a durability class. It names a layout lineage entry. Behavior: the engine opens the graph from the spec. An unbound spec refuses with a named reason before any effect. An unsupported spec refuses the same way. Wiring: extend the physical store binding in `crates/eg-storage`. Reuse the owner-store layout lineage registry (EG-DURABLE-KERNEL-R003). Reuse the store-authority binding (EG-DURABLE-KERNEL-R021). Refusal: the engine refuses a missing secret reference. It refuses an unknown variant. It refuses a layout absent from the lineage registry. Every refusal is atomic and typed. Evidence: the spec round-trips over the wire. Each refusal case stays typed with no state change. | `tests/test_object_storage_backend_spec.py::test_backend_spec_roundtrip_and_refusals` round-trips both variants. It asserts each refusal leaves the registry unchanged. |
| `EG-OBJECT-STORAGE-BACKEND-R002` | **Object-store read path.** Stage: durable kernel, object storage read. Caller: server bootstrap opening a graph whose `StorageBackendSpec` is `object-store` → `ObjectStoreBackend::open` → `ObjectFetcher::materialize(version)` in `crates/eg-storage/src/object/fetch.rs`. The restore tool of `EG-ENGINE-PARITY-R016.2` calls the same function for an earlier version. Layout under `<root>/<tenant>/<graph>/`: `HEAD` holds `{version, manifest}`; `manifests/<version:020>.json` is an immutable `VersionManifest { schema_version, tenant, graph, version, parent_version, snapshot, batches, digest }`; `segments/<sha256>.seg` holds content-addressed segments. A `SegmentRef` is `{ key, bytes, sha256 }` with 64 lowercase hex characters. A snapshot segment is the owner-table dump of `copy_declared_owner_tables`. A `BatchSegment` is a MessagePack list of `MutationBatchRecord`. Rule: `materialize(v)` reads manifest `v` and fetches its snapshot and batch segments. It verifies each SHA-256. It restores the snapshot into a local read-only store and replays the batches through the mutation kernel. A read never writes, copies or compacts the root. The local store is a cache that the root overrides. Refusals: `OBJECT_SEGMENT_MISSING` and `OBJECT_SEGMENT_DIGEST_MISMATCH`, each naming the version and key. Writes: none to the root. Depends on: R001 (`EG-OBJECT-STORAGE-BACKEND-R001`), `EG-DURABLE-KERNEL-R003`. | Test: `crates/eg-storage/tests/object_reads.rs::versioned_reads_and_corruption_refusal` (L2) materializes three versions against the in-memory object store and corrupts one segment. It asserts the typed refusal and that earlier versions stay intact. Verified by the root slice test `tests/test_object_storage_reads.py::test_cold_open_from_root` (L4). |
| `EG-OBJECT-STORAGE-BACKEND-R002.1` | **Hot-path proof.** Stage: durable kernel, object storage read. Caller: `epistemic-graph-server` started with an `object-store` spec on a loopback S3-compatible store → bootstrap → `ObjectStoreBackend::open`. Rule: the served test writes 100 nodes through a first engine and stops it. It deletes the local data directory and starts a second engine on the same root. It reads all 100 nodes. Refusals: a corrupted segment stops the open with `OBJECT_SEGMENT_DIGEST_MISMATCH`. Depends on: R002, R003. | Test: `tests/test_object_storage_reads.py::test_cold_open_from_root` (L4). |
| `EG-OBJECT-STORAGE-BACKEND-R003` | **Object-store commit path (commit before ack).** Stage: durable kernel, object storage commit. Caller: served `AddNode` → `commit_mutation_body` → `PersistenceBackend::commit_mutation_batch` → `ObjectStoreBackend::commit_mutation_batch` in `crates/eg-storage/src/object/backend.rs`. The backend wraps the local `RedbBackend` as a cache. Rule: only the Raft leader of the graph's group publishes. Step 1: commit locally. Step 2: upload the `BatchSegment` of this commit as an immutable segment. Step 3: put `manifests/<v+1>.json` with create-only mode. Step 4: update `HEAD` with a conditional put on its current version tag. Step 5: ack the caller. Step 4 is the fence. The ack carries the existing receipt shape. At open, a local store ahead of `HEAD` is discarded and rebuilt from the root. A local store behind `HEAD` replays the missing batches. Config: the spec's durability class decides when step 4 counts as durable; `object-sync` means the store acknowledged the conditional put. Refusals: `OBJECT_PUBLISH_STALE` when step 4 loses the conditional put. The node then stops publishing, discards its local commit and re-fetches `HEAD`. `OBJECT_DURABILITY_UNDECLARED` at open for a spec without a class. Evidence: a crash between steps 2 and 4 reopens at the prior version. The graph-copy row `EG-OBJECT-STORAGE-BACKEND-R003.2` consumes `RedbBackend::export_graph_raw_for_snapshot` and `import_graph_raw_from_snapshot`. Writes: root objects only. Depends on: R002, `EG-DURABLE-KERNEL-R016`. | Test: `crates/eg-storage/tests/object_commits.rs::commit_before_ack_and_partial_publish` (L2) interrupts between steps and reopens. It asserts the prior version is whole. It races two publishers and asserts one head. Verified by the root slice test `tests/test_object_storage_commits.py::test_ack_follows_head_update` (L4). |
| `EG-OBJECT-STORAGE-BACKEND-R003.1` | **Hot-path proof.** Stage: durable kernel, object storage commit. Caller: served `AddNode` on an engine with an `object-store` spec. Rule: the served test kills the engine process between segment upload and `HEAD` update. A fault hook in the loopback object store does this. It restarts the engine. It asserts the acked writes are present and the unacked write is absent. Depends on: R003. | Test: `tests/test_object_storage_commits.py::test_ack_follows_head_update` (L4). |
| `EG-OBJECT-STORAGE-BACKEND-R003.2` | **Graph copy from the redb store to the object-store root with a verified digest.** Subsystem: object-store backend, operator command. Entry point: `epistemic-graph-server store-upgrade graph-copy <data-dir> <graph> --to <object-root> --confirm`. Caller: `OperatorCommand::GraphCopy` in `src/operator_command.rs` → new `src/server/persistence/graph_copy.rs::copy_graph` → `RedbBackend::export_graph_raw_for_snapshot` → the object-store commit path of `EG-OBJECT-STORAGE-BACKEND-R003`. The command refuses while an engine holds the directory, as `EG-DURABLE-KERNEL-R070` does. `copy_graph` streams `RawGraphRows` in batches of 1,000 rows. Each batch carries a row count and a SHA-256 digest. The destination writes under a staging prefix and publishes its manifest only after the whole-graph digest matches the source. Cost is O(nodes + edges) with memory under 128 MiB. Copies of different graphs run in parallel. Refusals: `GRAPH_COPY_DIGEST_MISMATCH` leaves the destination empty, and `GRAPH_COPY_DESTINATION_NOT_EMPTY` writes nothing. Depends on: `EG-OBJECT-STORAGE-BACKEND-R001`, `EG-OBJECT-STORAGE-BACKEND-R003`, `EG-DURABLE-KERNEL-R070`. | Test: `tests/test_graph_copy_served.py::test_digest_mismatch_leaves_destination_empty` (L4) copies a seeded graph, corrupts one batch, and asserts the refusal and an empty destination. A second case copies cleanly and reads the graph from the object root. Nightly benchmark `benches/graph_copy.rs` (L6): p50 under 400 ms and p99 under 1,500 ms per 100,000 elements. |
| `EG-OBJECT-STORAGE-BACKEND-R004` | **Shared-root multi-node access.** Stage: identity and placement, object storage open. Caller: node bootstrap and the placement route handler → `ObjectStoreBackend::open` → `ObjectFetcher::materialize(HEAD)`. Any node opens any tenant graph from the shared root. Branch and commit coordination keep their owners: Raft for commits (R003) and the placement authority for routes. The store layer adds no second consensus. Rule: a node without a local copy fetches the `HEAD` manifest, its snapshot and batch segments in one bounded pass. It never replays history before the manifest snapshot. Config: key `object_store.open_parallel_fetches`, default 8, bounds [1, 64], unit requests, in the server config. A node that lost its local state reopens from the root with no data loss. A local cache whose version trails `HEAD` replays the missing batches before serving. Refusals: `PLACEMENT_NOT_GRANTED` when the node holds no placement route for the tenant, before any read (consumer row EG-PLACEMENT-R611.7). Writes: none to the root. Depends on: R003, `EG-PLACEMENT-R611`. | Test: `crates/eg-storage/tests/object_shared_root.rs::two_nodes_read_identical_state` (L2). Verified by the root slice test `tests/test_object_storage_shared_root.py::test_multi_node_cold_open_and_rejoin` (L4). It opens one root on two engines and drops one node's local state. It asserts identical served state after rejoin. |
| `EG-OBJECT-STORAGE-BACKEND-R005` | **Comparative cost gate across releases.** Stage: release qualification (nightly). Caller: the nightly suite job → `benches/object_store_cost.rs` → `scripts/object_store_cost_gate.py`. Code: add the bench with a `[[bench]]` entry in the root `Cargo.toml`. Add a `CountingObjectStore` wrapper over the `object_store` trait in `crates/eg-storage/src/object/counting.rs`. Rule: the harness drives one cold lifecycle against the current build and the previous release tag. The lifecycle is open, read 1,000 nodes, commit 100 batches and merge two branches. It records four dimensions: time, object actions, bytes and peak memory. Action and byte counts come from the counting run. Time and memory come from a separate matched run without the wrapper. Output is JSON lines with `schema_version`, `host`, `revision`, `lifecycle_digest`, `dimension`, `value`. Actions are counted per shard, which a single-store harness cannot express. The gate fails the release when object actions at open grow more than 10 percent. It compares with the previous release record in `benches/baselines/object_store_cost.json`. Refusals: `COST_RUN_UNSTAMPED` and `COST_RUN_UNPINNED` mark the run claim-ineligible; it never enters the evidence. Writes: the records file. Depends on: R003, `EG-DURABLE-KERNEL-R042`. Budget runs in the nightly suite (EG-DECISION-ENGINE-R178.1), never in a PR. | Test: `tests/test_comparative_cost_gate.py::test_regression_guard_and_claim_eligibility` (L4) injects a 15 percent growth of open actions and asserts the gate fails. It asserts an unstamped run is claim-ineligible. |
| `EG-OBJECT-STORAGE-BACKEND-R006` | **Archive segment put and get by sequence range.** Stage: durable kernel, object storage. Caller: the archiver of `EG-ENGINE-PARITY-R016.1` → `ObjectArchive::put_segment` and `get_segment` in `crates/eg-storage/src/object/archive.rs`. A segment holds the `BatchSegment` bytes of `EG-OBJECT-STORAGE-BACKEND-R002`. It is an immutable object at `<root>/archive/<tenant>/<graph>/<first:020>-<last:020>.seg`. Its manifest entry carries a SHA-256 digest. `put_segment` refuses an overlapping range with `ARCHIVE_RANGE_OVERLAP`. `get_segment` refuses a digest mismatch with `ARCHIVE_DIGEST_MISMATCH` (an existing code). Provider for `EG-ENGINE-PARITY-R016.1`. Depends on: `EG-OBJECT-STORAGE-BACKEND-R001`. | Test: `crates/eg-storage/tests/object_archive.rs::overlap_and_digest_refuse` (L2) against the in-memory object store. |
