# EG-OBJECT-STORAGE-BACKEND requirements

| ID | Requirement | Verification |
|---|---|---|
| `EG-OBJECT-STORAGE-BACKEND-R001` | **Typed object-store backend specification.** Model: a `StorageBackendSpec` declares the durable-store backend for a graph. Two variants exist. `local` is redb and is the default. `object-store` is S3-compatible. The spec names endpoint, bucket, and root by secret reference only. It declares a durability class. It names a layout lineage entry. Behavior: the engine opens the graph from the spec. An unbound spec refuses with a named reason before any effect. An unsupported spec refuses the same way. Wiring: extend the physical store binding in `crates/eg-storage`. Reuse the owner-store layout lineage registry (EG-DURABLE-KERNEL-R003). Reuse the store-authority binding (EG-DURABLE-KERNEL-R021). Refusal: the engine refuses a missing secret reference. It refuses an unknown variant. It refuses a layout absent from the lineage registry. Every refusal is atomic and typed. Evidence: the spec round-trips over the wire. Each refusal case stays typed with no state change. | `tests/test_object_storage_backend_spec.py::test_backend_spec_roundtrip_and_refusals` round-trips both variants. It asserts each refusal leaves the registry unchanged. |
| `EG-OBJECT-STORAGE-BACKEND-R002` | **Object-store read path.** Model: durable state on object storage is immutable content-addressed segments. A version manifest joins them. A snapshot read at a committed version fetches exactly the segments that version's manifest names. Behavior: reads never mutate store state. They trigger no copy-on-read. They trigger no compaction. Reads at any committed version are consistent with the commit chain. A corrupt segment refuses with a typed layout or corruption error. It never reinterprets. Wiring: extend the physical read path in `crates/eg-storage` with an object-store fetcher. Reuse the existing `GraphView` snapshot machinery. Refusal: the engine refuses a manifest naming a missing segment. It refuses a segment whose digest mismatches. Each refusal is typed and names the version. Evidence: a read at version N equals the write set at N. The corrupt-segment case refuses. Earlier versions stay readable. | `tests/test_object_storage_reads.py::test_versioned_reads_and_corruption_refusal` reads three versions. It corrupts one segment. It asserts the typed refusal with earlier versions intact. |
| `EG-OBJECT-STORAGE-BACKEND-R003` | **Object-store commit path (commit before ack).** Model: a commit writes immutable versioned segments. It publishes the new version by a single conditional manifest swap. The swap is a compare-and-set on the manifest object. The manifest carries version, digest, tenant, graph, and parent version. Behavior: the engine acks the client only after the manifest publish is durable. Durability follows the store's declared durability class. A failed or interrupted publish leaves the prior version intact. No partial version appears. No dangling publish appears. Wiring: extend the commit path with an object-store publisher. Reuse the commit/raft path. Reuse the existing receipt shape. Refusal: a publish that loses the CAS to a concurrent writer refuses as stale. It reconciles per the existing rules. A spec without a declared durability class refuses at open. Evidence: a crash between segment write and manifest publish reopens the graph at the prior version. The CAS-loss case never produces two heads. | `tests/test_object_storage_commits.py::test_commit_before_ack_and_partial_publish` interrupts publish between phases. It reopens. It asserts the prior version is whole. The concurrent-CAS case yields one head. |
| `EG-OBJECT-STORAGE-BACKEND-R004` | **Shared-root multi-node access.** Model: any engine node opens any tenant graph directly from the shared object-store root. Branch and commit coordination keep their existing owners. The consensus and placement authorities coordinate. The store layer adds no second consensus. Behavior: a node with no local pre-materialized copy serves tenant reads. It first re-fetches the current version's manifest and segments in a bounded pass. It never re-materializes full history. A node that lost local state reopens from the root. It loses no data. Wiring: extend the open and placement path (catalog-driven resharding, M3). Reuse the existing placement authority. Reuse the resharding handoff. Refusal: the engine refuses a node without a placement grant for the tenant. The refusal happens before reads. A stale local cache behind a newer manifest discards. It never serves. Evidence: two nodes open the same root. They read identical state. A node that drops local state rejoins from the root within the bounded re-fetch. | `tests/test_object_storage_shared_root.py::test_multi_node_cold_open_and_rejoin` opens one root on two nodes. It drops one node's local state. It asserts identical served state after rejoin. |
| `EG-OBJECT-STORAGE-BACKEND-R005` | **Comparative cost gate across releases.** Model: a pinned, environment-stamped comparative cost harness drives the same logical cold lifecycle against two builds. The lifecycle covers open, read, commit, and merge. The harness records four dimensions. Time, object actions, bytes, and peak memory. Output is versioned JSONL with a pass/fail reporter. Behavior: a bounded regression guard fails the release on unexplained growth in the fixed open cost. Storage-traffic and timing measurements use separate matched runs. A counting proxy perturbs timing. Wiring: add the harness under `benches/` and `scripts/`. Reuse the existing benchmark and cost-model machinery (transport benchmarks, multi-shard scaling, cost model). Refusal: the harness refuses a run missing its environment stamp. It refuses a run missing its pinned revision. The run is claim-ineligible. It never enters the gate's evidence. Evidence: an injected regression in the fixed open cost trips the guard. A clean run records the stamped JSONL. Stated advantage: the harness counts cross-shard federation actions. A single-store comparative harness cannot express those. | `tests/test_comparative_cost_gate.py::test_regression_guard_and_claim_eligibility` injects a fixed-cost regression. It asserts the release gate fails. It asserts an unstamped run is claim-ineligible. |
