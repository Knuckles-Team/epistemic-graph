# EG-ENGINE-PARITY — Requirements

Governing spec: [spec.md](spec.md).

Each row is one requirement. A child row `.n` is one five-minute unit of work. A row names the file it touches and the test that proves it. The generator sets each row's state in `status.json`.

| ID | Requirement | Acceptance |
|---|---|---|
| `EG-ENGINE-PARITY-R001` | **Single committer with group commit and batched fsync (rollup).** The engine must keep one committer per store file. The committer must batch concurrent write requests into one transaction and one fsync. Children `.1` to `.3` deliver it. | See each child. |
| `EG-ENGINE-PARITY-R001.1` | **Model and behavior.** Add `GroupCommitter{max_batch, max_wait_us}` in `crates/eg-storage/src/group_commit.rs`. Requests queue on a bounded channel. The committer drains up to `max_batch` requests or waits up to `max_wait_us`. One redb write transaction and one fsync cover the batch. Each request receives its own result. | `crates/eg-storage/tests/group_commit.rs::batch_shares_one_fsync` sends 64 requests and counts fsync calls. |
| `EG-ENGINE-PARITY-R001.2` | **Wiring and refusal.** Every durable write path calls the committer, beside the existing durability batching of EG-DURABLE-KERNEL-R016 and R040. A failed request in a batch refuses alone with its typed error. The other requests commit. A full queue refuses with `COMMIT_QUEUE_FULL`. | `crates/eg-storage/tests/group_commit.rs::one_failure_does_not_fail_batch` mixes one invalid request into a batch. |
| `EG-ENGINE-PARITY-R001.3` | **Hot-path proof.** The benchmark `crates/eg-storage/benches/group_commit.rs` commits 64 concurrent single-row writes. Throughput reaches at least 20,000 commits per second on the soak host. The p99 stays under 5 ms. | `cargo bench -p eg-storage --bench group_commit` fails on a 10 percent regression. |
| `EG-ENGINE-PARITY-R002` | **Optimistic concurrency with read and write sets (rollup).** A transaction must read from an MVCC snapshot and record its read set and write set. The committer validates both at commit. A conflict refuses with a typed error. Children `.1` to `.3` deliver it. | See each child. |
| `EG-ENGINE-PARITY-R002.1` | **Model and behavior.** Add `TxnFootprint{snapshot_seq, reads, writes}` in `crates/eg-transaction/src/occ.rs`. Keys are table and key ranges. Validation fails when a key in `reads` or `writes` changed after `snapshot_seq`. | `crates/eg-transaction/tests/occ.rs::write_skew_is_detected` runs two transactions over one invariant. |
| `EG-ENGINE-PARITY-R002.2` | **Wiring and refusal.** SQL, UQL and native mutation paths build the footprint. The group committer of R001 validates it. A conflict refuses with `TXN_CONFLICT{keys}` and writes nothing. It extends the version-checked writes of EG-DURABLE-KERNEL-R084. | `crates/eg-transaction/tests/occ.rs::conflict_refuses_and_writes_nothing` asserts the code and an unchanged store. |
| `EG-ENGINE-PARITY-R002.3` | **Hot-path proof.** The benchmark `crates/eg-transaction/benches/occ.rs` validates footprints of 100 keys. The added p99 per commit stays under 50 microseconds. | `cargo bench -p eg-transaction --bench occ` fails on a 10 percent regression. |
| `EG-ENGINE-PARITY-R003` | **Partitioned store files for parallel writers (rollup).** The engine must place each tenant, or each declared partition, in its own store file with its own committer. Writers to different files commit in parallel. Children `.1` to `.3` deliver it. | See each child. |
| `EG-ENGINE-PARITY-R003.1` | **Model and behavior.** Add `PartitionMap{key_rule, files}` in `crates/eg-storage/src/partition.rs`. The rule is `tenant` by default or a declared key prefix. One committer of R001 runs per file. | `crates/eg-storage/tests/partition.rs::two_partitions_commit_in_parallel` measures overlap of two writers. |
| `EG-ENGINE-PARITY-R003.2` | **Wiring and refusal.** The store registry of EG-DURABLE-KERNEL-R055 lists every partition file. A batch over two partitions uses the cross-store path of EG-DURABLE-KERNEL-R034 or refuses with `CROSS_PARTITION_BATCH`. | `crates/eg-storage/tests/partition.rs::cross_partition_batch_refuses_or_coordinates` submits one mixed batch. |
| `EG-ENGINE-PARITY-R003.3` | **Hot-path proof.** The benchmark `crates/eg-storage/benches/partition.rs` runs 8 tenants with 8 writers each. Total throughput reaches at least 6 times the single-file throughput of R001. | `cargo bench -p eg-storage --bench partition` fails on a 10 percent regression. |
| `EG-ENGINE-PARITY-R004` | **Lock-free acceptance for disjoint keys (rollup).** Concurrent transactions whose footprints do not overlap must all commit with no global lock. This generalizes the disjoint-path acceptance of EG-SCM-R003 to every key space. Children `.1` to `.3` deliver it. | See each child. |
| `EG-ENGINE-PARITY-R004.1` | **Model and behavior.** Add `disjoint(a, b) -> bool` over `TxnFootprint` in `crates/eg-transaction/src/occ.rs`. Disjoint footprints validate without a wait. | `crates/eg-transaction/tests/occ.rs::disjoint_footprints_never_wait` runs 32 disjoint writers. |
| `EG-ENGINE-PARITY-R004.2` | **Wiring and refusal.** EG-SCM-R003 calls the same function for path sets. A repeated conflict on the same keys refuses after 3 retries with `TXN_RETRY_EXHAUSTED`. | `crates/eg-transaction/tests/occ.rs::retry_bound_refuses` forces 4 conflicts. |
| `EG-ENGINE-PARITY-R004.3` | **Hot-path proof.** The benchmark `crates/eg-transaction/benches/disjoint.rs` runs 32 disjoint writers. No writer waits on another at p99. | `cargo bench -p eg-transaction --bench disjoint` fails on a 10 percent regression. |
| `EG-ENGINE-PARITY-R005` | **Write throughput benchmark and targets (rollup).** The engine must hold one write benchmark suite with stated targets. A change that lowers a target fails the benchmark gate of EG-DURABLE-KERNEL-R042. Children `.1` to `.3` deliver it. | See each child. |
| `EG-ENGINE-PARITY-R005.1` | **Model and behavior.** Add `benches/engine_writes.rs` with five workloads: single-row commit, 64 concurrent writers, 8 partitions, bulk load and conflict-heavy. plan.md states the target for each. | `benches/engine_writes.rs` prints one record per workload. |

| `EG-ENGINE-PARITY-R005.3` | **Hot-path proof.** The suite runs on the soak host on each release candidate. Each result carries host, revision and data digest. | `cargo bench --bench engine_writes` against the stored baseline. |

| `EG-ENGINE-PARITY-R008` | **Catalog views for outside tools (rollup).** The engine must serve `pg_catalog` and `information_schema` views that outside tools read at connect. The views derive from the engine catalog through the columnar engine. Children `.1` to `.3` deliver it. | See each child. |
