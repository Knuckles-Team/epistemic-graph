# EG-FEDERATED-QUERY requirements

| ID | Requirement | Verification |
|---|---|---|
| `EG-FEDERATED-QUERY-R001` | **Bounded derivation steps in EL+/RL and tableau reasoning.** The EL+/RL and tableau reasoners enforce a derivation-step budget while checking consistency and classifying the schema, and fail closed with a typed VALIDATION_BUDGET_EXCEEDED error instead of running without bound. Consistency checking reports no unsatisfiable classes on the shipped ontology corpus. | A unit test exercises budget exhaustion to confirm the typed refusal, and an integration test checks consistency across the full corpus. |
| `EG-FEDERATED-QUERY-R002` | **Rejection reasons stay out of the core kernel row schema.** When a query or validation is rejected, the engine reports the rejection reason through the caller's log, metric, or domain-specific error channel rather than adding it as a field on the core kernel row structure. The kernel row format remains format-neutral and unchanged by the content of any given rejection reason. | A contract test confirms the kernel row schema carries no rejection-reason field, and a negative test confirms the reason is still observable through logs or returned error metadata. |
| `EG-FEDERATED-QUERY-R003` | **Derivation-step budget is enforced once, not duplicated per path.** The derivation-step budget that bounds EL+/RL and tableau reasoning is implemented a single time and applies to every reasoning entry point, including the path that composes and classifies the schema. This specification defines no separate step-budget enforcement here; that guarantee is owned by the typed-packs-and-catalog specification's schema composition work. | Covered by the step-budget enforcement test defined under the typed-packs-and-catalog specification; this specification requires no additional test for this item. |
| `EG-FEDERATED-QUERY-R004` | **Reasoning projection rebuilds after any skipped event.** If the reasoning projection misses or skips an update event, the engine triggers a full rebuild of the projection before serving any further reads from it, rather than serving results derived from an incomplete projection state. | An integration test injects a skipped projection event and confirms the engine rebuilds before serving reads. |
| `EG-FEDERATED-QUERY-R005` | **UQL VALIDATE SHAPE stage.** UQL includes a VALIDATE SHAPE stage that checks query results or graph data against a declared shape definition and reports conformance or the specific violations found, as part of standard UQL execution. | An integration test runs VALIDATE SHAPE over fixtures with conforming and violating data and checks the reported conformance result. |
| `EG-FEDERATED-QUERY-R006` | **Proof-carrying results for SPARQL and rule-derived queries.** A caller can request a proof alongside SPARQL or rule-derivation query results, and the returned proof states the premises used and the schema or index generation they were checked against, remaining consistent across the Rust server and the generated Python client. | An integration test requests a proof-carrying query, verifies the proof's premises against the serving generation, and confirms the proof survives the client wire format. |
| `EG-FEDERATED-QUERY-R007` | **Semantic-index reconciliation tombstones only on a complete proof.** Semantic-index reconciliation marks a source's entries as tombstoned only after an authoritative complete-snapshot proof confirms the source is genuinely missing; an interrupted or partial scan leaves the prior live entries untouched. When reconciliation refuses to proceed, it distinguishes an absent source from one whose proof is unissued or expired so the failure names the actual condition. | A regression test interrupts a source scan before the complete-snapshot proof and confirms no tombstone is created, then replays a complete scan and confirms exactly the absent sources are tombstoned. |
| `EG-FEDERATED-QUERY-R008` | **Edge-native text and vector search with stable identity.** The engine indexes and retrieves edges directly by text and vector similarity, without requiring edges to be reified into nodes, using a stable identity for parallel edges between the same pair of nodes. Searches apply tenant, purpose and row-level-security prefilters before candidate truncation, update and delete against the index are safe to replay, and the set of indexable targets is defined once and generated consistently into every client. | A correctness oracle compares filtered edge-search results against an unfiltered full scan, a replay test confirms idempotent update/delete behavior, and a generated-contract check confirms the target set matches across clients. |
| `EG-FEDERATED-QUERY-R009` | **Durable user-managed graph-index lifecycle.** A caller can create, check the status of, and drop a graph index through one durable, user-managed lifecycle that extends the engine's existing index-manager authority. Backfill is fenced against concurrent writes, activation is atomic, a blocked or partial index state is diagnosable, and the index recovers correctly after a restart, with the query planner falling back safely when a needed generation is unavailable. | An integration test exercises create, backfill, activate and drop plus a restart during backfill, and confirms atomic activation, diagnosable blocked state, and correct planner fallback. |
| `EG-FEDERATED-QUERY-R010` | **Tableau reasoning stays bounded on the shipped core schema.** Tableau-based consistency and classification reasoning over the shipped core schema completes within bounded time and memory, without exponential blowup or stack overflow from schema-axiom internalization and backtracking. Schema composition and restart replay that depend on this reasoning path complete successfully under normal resource limits. | A performance and fault test composes and classifies the full core schema under a restart-replay scenario and confirms it completes within declared time and memory budgets without overflow. |
| `EG-FEDERATED-QUERY-R011` | **EL+/RL reasoning is sound against the shipped ontology corpus.** The EL+/RL reasoner derives only sound subsumption and disjointness conclusions, so checking the shipped core ontology corpus reports it as consistent with no unsatisfiable classes, including owl:Nothing and its root class. The EL/RL and tableau reasoning paths agree on consistency and disjointness results over this corpus. | A full-corpus consistency regression test checks the shipped ontology for unsatisfiable classes and confirms the EL/RL and tableau results agree. |
| `EG-FEDERATED-QUERY-R012` | **Tableau honors AllDisjointClasses and core disjointness facts.** Tableau-based reasoning expands owl:AllDisjointClasses declarations the same way the EL path does, so schema-entry full-ABox checking enforces the core disjointness between information-content entities, generically-dependent continuants, processes and temporal regions, and between persons, organizations, servers and events. The corresponding fact that a taxon is never an organism is present and enforced. | An integration test checks that tableau reasoning rejects instances violating these disjointness constraints, including the taxon/organism fact. |
| `EG-FEDERATED-QUERY-R013` | **Foreign-source resolution is scoped to the owning principal.** Registered foreign sources are keyed by owning tenant and actor rather than by name alone, so a caller with general federated-query access cannot name another principal's registered source and have the engine use its stored credentials on their behalf. Resolving a foreign source outside the registering principal's scope is refused with a stable ACCESS_DENIED error, and foreign-source rows are documented as not row-level-security filtered. | A negative integration test registers a foreign source under one principal and confirms a different principal's query naming that source is refused with ACCESS_DENIED. |
| `EG-FEDERATED-QUERY-R014` | **Explicit grant-based sharing of a registered foreign source.** A principal who owns a registered foreign source can share query access to it with another principal through the engine's existing role-based access-control grant mechanism, rather than through an implicit name lookup. The registering principal retains ownership of the source, and access can be granted and later revoked. | An integration test grants another principal access to a foreign source, confirms it can query through the grant, then revokes the grant and confirms the query is refused. |
| `EG-FEDERATED-QUERY-R015` | **Read-only enforcement at the shared SQL execution path.** The shared graph-free SQL execution path classifies and refuses DDL, DML, COPY and CREATE EXTERNAL TABLE statements as not read-only, enforced once at that shared path rather than duplicated per caller. Every caller that reaches this path, including observability log search, is subject to the same refusal. | A test sends DDL, DML, COPY and CREATE EXTERNAL TABLE statements through each caller of the shared SQL path, including log search, and confirms each is refused. |
| `EG-FEDERATED-QUERY-R016` | **UQL AS OF uses Unix-second timestamps, not ISO dates.** UQL's AS OF clause takes a Unix-second timestamp, and query stages chain using the published UQL stage-separator syntax rather than Cypher-shaped text or an ISO-8601 timestamp; text that does not match this grammar is rejected as invalid rather than silently accepted. A conformance test confirms that UQL text emitted by any client parses successfully against the current grammar. | A parser test feeds the correct stage-chained, Unix-second AS OF form and confirms it parses, and a negative test confirms Cypher-shaped or ISO-timestamp text is rejected. |
| `EG-FEDERATED-QUERY-R017` | **Dependency tracking covers edge-type and embedding generations.** Query plans that perform graph traversal or embedding-based ranking register their dependency on the specific edge types and embedding generations they read, so a write that changes an unrelated edge type or generation does not invalidate the plan, while a write touching a real dependency correctly does. | A test performs disjoint writes against unrelated edge types and embedding generations and confirms an existing traversal/rank plan is not invalidated, while a dependent write does invalidate it. |
| `EG-FEDERATED-QUERY-R018` | **Class-level volatility drives invalidation and cache freshness.** Classes and sources declare an eg:volatilityClass, and a per-class invalidation event fires when matching data changes. Foreign-source result caching only serves a cached result when the relevant source watermark is current, consistent with the volatility class declared for that data. | A test changes data in a declared volatility class, confirms the corresponding invalidation event fires, and confirms the foreign-source cache only serves fresh, watermark-current results. |
| `EG-FEDERATED-QUERY-R019` | **Per-bar signal-state advancement with revisable trend records.** On each bar finalization, the complex-event-processing layer advances signal state and records a TrendFlip event; a later correction can revise a previously recorded TrendFlip without losing the revision history. A scanner index exposes the latest signal state per series for efficient lookup. | A test finalizes a sequence of bars, confirms signal state advances and TrendFlip records are created, then issues a revision and confirms both the historical and latest-state views are correct. |
| `EG-FEDERATED-QUERY-R020` | **One query-text method surface, with the legacy method retired.** The engine serves exactly one query-text method, Method::Uql; the legacy UnifiedQueryText method and its callers, including remote-engine federation and server tests, are migrated to it, and UnifiedQueryText is removed from the codebase with no compatibility alias or deprecation shim. | A contract test confirms UnifiedQueryText no longer exists in the method registry, and an integration test confirms remote-engine federation operates correctly over Method::Uql. |
| `EG-FEDERATED-QUERY-R021` | **Full UQL predicate algebra with SQL-consistent evaluation.** UQL's predicate algebra supports the comparison operations, AND/OR/NOT with parentheses, IN, BETWEEN, IS [NOT] NULL, typed literals, JSONPath access and spatial predicates. The per-row three-valued evaluator used by UQL agrees with the equivalent SQL evaluation on every supported predicate, including null handling. | A differential test evaluates the same predicate set through SQL and the UQL per-row evaluator across null and non-null fixtures and confirms identical results. |
| `EG-FEDERATED-QUERY-R022` | **UQL source clauses are first-class, with typed empty-result cases.** UQL treats MATCH, SPARQL, TSSCAN, SENSOR FUSE/ALIGN, SPATIAL/TENSOR SCAN and FOREIGN SCAN/HTTP as first-class source clauses in its grammar and planner. A head-transform stage that would yield an empty result set emits the UQL_W_HEAD_TRANSFORM_YIELDS_EMPTY warning instead of silently reseeding from the runtime, and runtime empty-set reseeding is no longer part of the documented language. | A parser and planner test exercises each source clause and confirms a head-transform-to-empty case emits the warning rather than reseeding. |
| `EG-FEDERATED-QUERY-R023` | **Every query modality has a published UQL spelling.** UQL provides a syntax for every supported query modality: SPARQL/VAR, user-defined functions, FOREIGN SCAN/HTTP with any credential-bearing inline source specification refused, spatial functions including BUFFER, INTERSECTION and DIFFERENCE plus REPROJECT, tensor SLICE/REDUCE/ADD and related tensor functions, complex-event patterns such as SEQ/WITHIN/ABSENCE over SLIDING/TUMBLING windows, SENSOR ALIGN, probabilistic PROB, FUSE K, REASON ONTOLOGY, bounded WINDOW, and VALIDATE SHAPE. | A grammar-exhaustiveness test parses a program covering every listed construct and confirms each round-trips through the canonical printer, and a negative test confirms a credential-bearing FOREIGN SCAN/HTTP specification is refused. |
| `EG-FEDERATED-QUERY-R024` | **Traversal syntax compiles to one canonical Expand encoding.** UQL's directional traversal arrows, the wildcard hop syntax and edge predicate filters all compile to the budget-checked, shortest-hop Op::Expand plan node. The common case of an unfiltered, unbounded, outbound single-relationship expansion is always encoded the same way, spelled Traverse, so the planner has one canonical representation rather than multiple equivalent encodings. | A planner test compiles equivalent traversal syntaxes and confirms they produce the identical Op::Expand/Traverse plan node. |
| `EG-FEDERATED-QUERY-R025` | **Typed parameter binding end-to-end through the Python client.** UQL's typed $param placeholders bind only in parser-recognized value positions and are type-checked, with unbound, mistyped or unused parameters failing as typed errors. The engine serves this through Method::Uql with text and params fields, and the generated Python client exposes a matching uql(text, params) call; values never pass through text interpolation. | A test sends injection-shaped parameter values through the Python client and confirms they bind as typed values rather than altering the executed query, plus negative tests for unbound, mistyped and unused parameters. |
| `EG-FEDERATED-QUERY-R026` | **UQL documentation is test-verified with an embedded grammar.** docs/uql.md documents the current UQL language with every example in a uql code block actually parsing under a dedicated test, and embeds the generated grammar rather than a hand-maintained copy. docs/analytics_in_uql.md clearly separates which analytics run through SQL from which run through UQL stages. | A documentation test parses every uql-tagged code block in docs/uql.md and fails the build if any example does not parse. |
| `EG-FEDERATED-QUERY-R027` | **EXPLAIN, PROFILE and RETURN support multi-stage UQL programs.** A UQL program that composes named LET/JOIN subplans into a dependency graph supports EXPLAIN and PROFILE output and RETURN channels the same as a single-stage query, rather than refusing with UQL_UNSUPPORTED. | An integration test runs EXPLAIN and PROFILE over a multi-stage LET/JOIN program and confirms per-stage plan and runtime information is returned instead of a refusal. |
| `EG-FEDERATED-QUERY-R028` | **KnowledgeSet is reachable from UQL.** A UQL query can read a KnowledgeSet, combining epistemic status, FUSE and AS OF semantics within a single query, and produces results equivalent to issuing the corresponding operations through the structured query surface or the previously separate surfaces. | An oracle test runs equivalent epistemic, fuse and as-of queries through UQL, the structured surface and the prior separate surfaces and confirms the results agree. |
| `EG-FEDERATED-QUERY-R029` | **UQL text from graph-exploration clients matches the grammar.** Any UQL text generated by a graph-exploration client, including a temporal scrubber control, uses the stage-chained syntax and a Unix-second AS OF timestamp defined by the published UQL grammar, not Cypher-shaped text or an ISO-8601 timestamp. Text that does not conform to this grammar is rejected with a typed parse error rather than silently misinterpreted. | A conformance test parses the exact text emitted by the temporal-scrubber control's query template and confirms it succeeds under the current grammar. |
| `EG-FEDERATED-QUERY-R030` | **TSSCAN preserves per-series row identity and full precision.** The TSSCAN source identifies each time-series row by series@ts and carries its values as f64 channels named v0..vk, so rows from different series at the same timestamp never collide and no value is truncated to f32. This row identity is the basis for series analytics expressed in UQL. | A fixture test scans overlapping multi-series data through TSSCAN and confirms no row collisions, no truncation and correct per-series, per-timestamp identity. |
| `EG-FEDERATED-QUERY-R031` | **Contribution attribution kernels exposed through UQL ATTRIBUTE.** The engine computes contribution attribution using linear split, exact Shapley for small coalitions, seeded sampled Shapley with a confidence interval, Owen values over a hierarchy, and multi-factor OLS regression with heteroskedasticity-and-autocorrelation-consistent standard errors. UQL exposes these through an ATTRIBUTE channel VALUE agg SHAPLEY [SAMPLES n SEED s] stage, and a decision-evaluation report can attribute an assembly slate's outcome across its logged sub-slates. | Exact Shapley results are checked against a brute-force oracle, sampled Shapley against seeded-repeatability and confidence-interval-coverage tests, and the ATTRIBUTE UQL stage against an integration test. |
| `EG-FEDERATED-QUERY-R032` | **Probabilistic impact propagation with cone-scoped recomputation.** The engine propagates probabilistic impact across the graph using an exact Noisy-OR model on acyclic structure with a bounded unroll on cycles, and an Independent-Cascade model using seeded Monte Carlo simulation with a confidence interval, following ontology-declared edge transmission. Results report the top-k contributing paths with per-seed attribution, are exposed in UQL as PROPAGATE model edge-pattern HOPS n, and a standing query seeded from Incident, ConformanceViolation or CVE facts recomputes only the affected cone and records ImpactAssessment facts. | A test compares the Noisy-OR result against an exact enumeration on small acyclic graphs and the Independent-Cascade result against seeded-repeatability and confidence-interval checks, plus an integration test for the PROPAGATE stage and standing-query cone recomputation. |
| `EG-FEDERATED-QUERY-R033` | **Barrier-hit and time-to-exhaustion derivations, one shared CDF.** The engine computes first-passage probability for a barrier using the arithmetic-Brownian-motion inverse-Gaussian form and the geometric-Brownian-motion log-barrier form, each checked against a terminal-distribution calculation, with maximum-likelihood drift and volatility estimation and a bootstrap confidence interval. These are exposed as DERIVE barrier_hit(...) and DERIVE tte(...), and all normal-tail calculations use one public stats::norm_cdf implementation rather than a separate private copy. | Results are checked against a Monte Carlo simulation and against the analytic limit as volatility approaches zero, which must match the deterministic linear-prediction case. |
| `EG-FEDERATED-QUERY-R034` | **Motif and discord search over time series, batch and streaming.** The engine finds motifs and discords in time series using an FFT-accelerated MASS distance computation and a matrix profile, computed anytime for batch data and incrementally for streaming data. UQL exposes MOTIF LIKE $shape LENGTH m TOP k and DISCORD LENGTH m TOP k under the standard query budgets, anomaly mining supports a matrix-profile discord algorithm, and a series shape predicate can emit a stream event consumed by the existing complex-event-processing matcher. | A test compares matrix-profile motif and discord results against a brute-force distance computation on a reference series and confirms the streaming and batch computations agree. |
| `EG-FEDERATED-QUERY-R035` | **Filtered text search evaluates within the filtered candidate set.** A text search combined with a filter evaluates its relevance ranking only within the set of rows that satisfy the filter, using a filtered index scan or equivalent pre-filtering, so a filtered query returns up to k relevant results drawn from the full matching set rather than filtering after an unfiltered top-k ranking has already discarded relevant rows. | A correctness oracle compares filtered BM25 search results against an unfiltered full scan intersected with the filter and confirms they agree. |
| `EG-FEDERATED-QUERY-R036` | **Bounded, observable graph reopen after a restart.** After a restart, the engine serves reads from stored data immediately and rebuilds or restores its index state either from persisted index state or incrementally in the background, rather than blocking all reads on a full linear index rebuild.
