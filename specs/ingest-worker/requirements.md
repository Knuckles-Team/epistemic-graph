# EG-INGEST-WORKER requirements

| ID | Requirement | Verification |
|---|---|---|
| `EG-INGEST-WORKER-R001` | **Ingest worker capability is served by the engine queue and run by the SDK runner (rollup).** Replaces agent-utilities `kg-ingest-worker` (ingest_worker.py, deleted by commit b02e39950). Split into `EG-INGEST-WORKER-R001.1`-`EG-INGEST-WORKER-R001.17`; satisfied only when every child is satisfied. | See each child. |
| `EG-INGEST-WORKER-R001.1` | **Typed ingest job envelope with refusal tests.** `eg-types` (file to be created: crates/eg-types/src/ingest_job.rs) defines `IngestJobEnvelope{job_id, tenant, corpus_key, kind, target, attempt}`. A blank job_id, blank target, unknown kind or attempt above the retry ceiling is refused with a typed error. | Unit tests in the same file cover each refusal and a serde round trip. |
| `EG-INGEST-WORKER-R001.2` | **Typed job kinds and lane derivation.** One `IngestJobKind` enum (document, codebase, skill_workflows, capability_hydration) and one pure function `lane_for(kind)` returning hydration for skill_workflows and capability_hydration, general otherwise, in the same file as R001.1. | Unit test asserts the lane for every kind. |
| `EG-INGEST-WORKER-R001.3` | **Partition key function.** One pure function `partition_key(envelope)` in the same file returns the tenant, then corpus, then kind hierarchy so the queue can keep per-tenant and per-corpus ordering without global serialization. | Unit test asserts equal keys for jobs of one corpus and different keys across tenants. |
| `EG-INGEST-WORKER-R001.4` | **Enqueue maps onto the served task queue with deterministic ids.** One function `enqueue_ingest_job` in crates/eg-capabilities/src (file to be created: ingest_queue.rs) wraps `TaskQueueEnqueue` from EG-DURABLE-KERNEL-R072 on queues `ingest` and `ingest-hydration`, deriving the task id from job_id so a duplicate enqueue is a no-op. | Integration test enqueues the same job twice and asserts one claimable task. |
| `EG-INGEST-WORKER-R001.5` | **Prerequisite: durable task queue (this repository, EG-DURABLE-KERNEL-R071, R072, R073).** Typed enqueue/claim/ack model, served RPC pair and generated Python client methods must land before R001.4 and R001.11. Not re-specified here. | Linked rows verified by their own tests. |
| `EG-INGEST-WORKER-R001.6` | **Prerequisite: worker registry, reserved admission and scheduler floors (this repository, EG-DURABLE-KERNEL-R074, R075, R076).** The reserved hydration floor in R001.10 is computed from the served `SchedulerConfig` lane floors, not a worker-side environment knob. | Linked rows verified by their own tests. |
| `EG-INGEST-WORKER-R001.7` | **Typed retry policy with validation.** One `IngestRetryPolicy{max_attempts, base_delay, max_delay, jitter}` model in the same file as R001.1; zero attempts, base above max, or negative jitter is refused. | Unit tests for each refusal. |
| `EG-INGEST-WORKER-R001.8` | **Retry delay function with jitter.** One function `next_delay(policy, attempt, seed)` returns a bounded exponential delay with jitter so idle or failed workers do not retry in lockstep. | Unit test asserts the bound, monotonic growth and that two seeds differ. |
| `EG-INGEST-WORKER-R001.9` | **Failure routing: retry then dead letter.** The ack path of R001.4 maps a failed outcome to redelivery with `next_delay` while attempts remain, and to a dead-letter record carrying the last error once exhausted. Reuse the SourceIngest dead_letter capability named in EG-REPO-INGEST-R002 rather than a second dead-letter writer. | Integration test fails a job past max_attempts and asserts one dead-letter record and no further delivery. |
| `EG-INGEST-WORKER-R001.10` | **Hydration-reserved lane served as a distinct queue.** Claim on `ingest-hydration` is admitted first for reserved workers using `AdmitWorkerTask` (EG-DURABLE-KERNEL-R075); a lone worker is never fully reserved. | Integration test with a one-worker pool asserts it still claims general work; with two, one claims hydration first. |
| `EG-INGEST-WORKER-R001.11` | **Backpressure read and producer refusal.** One read op `IngestQueueDepth` returns depth and oldest-age per queue. `enqueue_ingest_job` refuses above a configured depth with stable code INGEST_QUEUE_FULL and bounded detail so producers can slow down. | Integration test fills the queue to the limit and asserts the refusal code and that depth is unchanged. |
| `EG-INGEST-WORKER-R001.12` | **Lease renewal for long jobs.** The runner renews the claim through the existing `RenewWorkItemLease` method at a third of the lease. A missed renewal lets the job redeliver. Already provided by the work-item coordination domain. Verify with a test. | Integration test pauses renewal and asserts redelivery after expiry. |
| `EG-INGEST-WORKER-R001.13` | **Ingest queue metrics.** Engine exports gauges `eg_ingest_queue_depth`, `eg_ingest_oldest_age_seconds` and counters `eg_ingest_jobs_total{outcome}`, `eg_ingest_dead_letter_total`, from the R001.11 read. | Metrics test scrapes after one success, one retry and one dead letter and asserts the values. |
| `EG-INGEST-WORKER-R001.14` | **Cross-repo (connector SDK repository): ingest worker runner.** Add a runner module with one function `run_ingest_worker` that claims through the generated client, executes the job body, acks success or failure, and commits only after the ack (at-least-once). The job body reuses the SDK's existing source-effect runners; EG holds no source credentials. | SDK unit test with a fake client asserts ack after execution and no ack when the body is killed. |
| `EG-INGEST-WORKER-R001.15` | **Cross-repo (connector SDK repository): CLI entry point and autosize.** Add one console command `ingest-worker` with `--workers` (default CPU and memory autosized, 0.36 of cores, 3 GiB per worker) and `--engine-endpoint`; it fails loud with a non-zero exit if the engine is unreachable or lacks the task-queue methods before claiming anything, and drains on SIGTERM. | CLI test asserts exit code 2 against an unreachable engine and clean drain on SIGTERM. |
| `EG-INGEST-WORKER-R001.16` | **Cross-repo (graph-os): host and supervise the worker.** graph-os declares the worker as a supervised deployment unit and surfaces its health and the R001.13 metrics through its existing health route. It does not contain job logic. | Graph-os health test asserts a stopped worker shows as unhealthy. |
| `EG-INGEST-WORKER-R001.17` | **Parity test against the deleted module.** One test enumerates the parity table in plan.md and asserts every row marked exists or to-build has a passing proving test, and rows marked dropped carry a reason. | The test runs in the spec checks. |
| `EG-INGEST-WORKER-R002` | **Ontology induction from text stays a draft until it passes checks (rollup).** The ingest worker must propose classes and properties from unstructured text, then populate instances against that proposal. A proposal must be admitted only after property-coverage and redundancy checks pass. Otherwise it must stay a draft [arXiv:2511.11017]. | Tests prove a passing proposal is admitted and a failing one stays a draft. |
| `EG-INGEST-WORKER-R002.1` | **Model.** `crates/eg-types/src/ontology_proposal.rs` must define `OntologyProposal` with classes, properties, a `state` of `Draft` or `Admitted`, and provenance. New proposals must start as `Draft`. | Unit test round-trips a proposal and asserts the initial state. |
| `EG-INGEST-WORKER-R002.2` | **Behavior.** `score_proposal` must compute property coverage and class redundancy. The defaults should be coverage of at least 0.8 and redundancy of at most 0.1, replaced by measurement. | Unit test checks three proposals against both thresholds. |
| `EG-INGEST-WORKER-R002.3` | **Wiring.** The `ingest_document` job body must call `score_proposal` after induction. This row creates the call site in `crates/eg-capabilities/src/ingest_queue.rs`, reached from the runner of R001.14. | Test runs one document job and asserts the check ran. |
| `EG-INGEST-WORKER-R002.4` | **Refusal.** A proposal that fails a check must stay `Draft` and return `PROPOSAL_NOT_ADMITTED` with the failing check. Instances must not populate against it. | Test fails coverage and asserts the draft state and zero instances. |
| `EG-INGEST-WORKER-R002.5` | **Evidence.** Each job must record `coverage`, `redundancy` and `decision` in its trace. | Test reads the trace after one admitted and one draft job. |
| `EG-INGEST-WORKER-R002.6` | **Hot-path proof.** The entry point is the served ingest queue claim. A worker claims a document job and the passing proposal must reach `Admitted`. | Integration test `tests/ingest_ontology_induction.rs` runs one passing and one failing document and asserts both states. |
| `EG-INGEST-WORKER-R003` | **Documents become typed knowledge atoms with mandatory provenance (rollup).** The ingest worker must decompose documents and interactions into typed atoms, each with a provenance key. A query must select only relevant atoms to build context. Children `.1` to `.18` cover atoms, normalized documents and transcript records. [arXiv:2606.12400] [arXiv:2606.19847] | Satisfied only when `.1` to `.18` are verified. |
| `EG-INGEST-WORKER-R003.1` | **Model.** `crates/eg-types/src/knowledge_atom.rs` (new; search terms in `plan.md`) must define `KnowledgeAtom` with `atom_id`, `kind`, `text`, `provenance_key` and `tenant`. The `kind` set is closed: fact, event, preference, procedure. | Unit test round-trips an atom and rejects an unknown kind. |
| `EG-INGEST-WORKER-R003.2` | **Behavior.** `decompose(document, policy)` must emit atoms from the parsed chunks of `crates/eg-document/src/contract.rs:141`. `select_atoms(query, atoms, budget)` must rank atoms by relevance and stop at the token budget. Both defaults should be replaced by measurement. | Unit test decomposes one document and selects under a budget. |
| `EG-INGEST-WORKER-R003.3` | **Wiring.** The `ingest_document` job body must call `decompose` and store atoms. This row creates the call site in `crates/eg-capabilities/src/ingest_queue.rs`, reached from the runner of R001.14. The context query path must call `select_atoms`. No production caller exists for either function today. | Test runs one document job and asserts atoms exist. |
| `EG-INGEST-WORKER-R003.4` | **Refusal.** An atom without a provenance key must return `ATOM_PROVENANCE_MISSING` and must not be stored. A query over zero relevant atoms must return an empty context, not a guess. | Test submits an atom without provenance and asserts the refusal and zero stored atoms. |
| `EG-INGEST-WORKER-R003.5` | **Evidence.** Each job must record `atoms_emitted`, `atoms_refused` and the context query must record `atoms_selected` and `tokens_used` in its trace. | Test reads the trace after one job and one query. |
| `EG-INGEST-WORKER-R003.6` | **Hot-path proof.** The entry point is the served ingest queue claim. A worker claims a document job. A later query assembles context from atoms alone and cites each provenance key. | Integration test `tests/ingest_knowledge_atoms.rs` ingests one document, queries it and asserts selected atoms and provenance. |
