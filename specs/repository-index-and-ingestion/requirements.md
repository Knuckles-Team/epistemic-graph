| `EG-REPO-INGEST-R009.1` | **Edge identity is the `(source, target, relation_type)` triple.** EG's `eg-core` graph treats an edge's identity as the `(source_id, target_id, relation_type)` triple rather than the bare `(source_id, target_id)` pair, so multiple relation types between the same two endpoints coexist as distinct addressable edges instead of silently colliding. An untyped legacy edge migrates deterministically onto this scheme by reading its stored blob's `type`/`label` field as `relation_type`, falling back to `related_to` when neither is present; a collision between two untyped edges that migrate to the same triple is resolved by a deterministic collapse rule (keep one, emit a collision receipt) rather than by dropping either silently. | A collision test adds two untyped edges between the same pair that migrate onto the same `relation_type`, confirms the deterministic collapse and its collision receipt, and a typed-edge test confirms distinct relation types between the same pair are independently addressable, retrievable and removable. |

| `EG-REPO-INGEST-R010` | **Tree-sitter grammar coverage expands to 18 more languages.** EG's native parser (parser/tree_sitter.rs) adds tree-sitter grammar support for Swift, Kotlin, Objective-C, Zig, Julia, Elixir, Groovy, PowerShell, Fortran, Pascal, Verilog, CUDA, HTML, CSS, JSON, Terraform/HCL, and DreamMaker, alongside its existing C, C++, C#, Go, Rust, Python, JavaScript, TypeScript, React, Java, Scala, Ruby, PHP, Lua, Bash, and SQL support; DreamMaker, lacking a maintained tree-sitter grammar, uses a custom extractor. | A grammar-expansion test suite parses a representative fixture for each newly added language and confirms a successful parse outcome for each. |
| `EG-REPO-INGEST-R011` | **Ingestion community detection uses pure Leiden.** EG's ingestion community detection uses pure Leiden partitioning via the shared driver in graph_algos/leiden.rs, wired through algorithms.rs and features.py, not a Louvain/Leiden hybrid, because Louvain alone can produce badly connected or fully disconnected communities that would otherwise be trusted as valid modules. | A community-detection test confirms ingestion's partitioning path invokes Leiden's refinement phase and that no committed community in a test graph is internally disconnected. |
