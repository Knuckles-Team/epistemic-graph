| `EG-REPO-INGEST-R004` | **Derived series maintained incrementally with lineage.** EG's timeseries handlers support a SeriesDefine{name, expr, sources} mutation that creates a derived series incrementally maintained from each source's prior append history; a revision replay only appends new series values, never mutates past ones, and the graph records DerivedSeries derivedFrom Series lineage together with the defining expression's digest. Row-level security on a derived series is the most restrictive policy among its sources, a cyclic source definition is refused, and maintenance work is bounded by an explicit budget. | An integration test defines a derived series, appends to its sources, confirms incremental maintenance matches full recomputation, and negative tests confirm a cyclic definition is refused and an over-budget maintenance run is bounded. |
| `EG-REPO-INGEST-R005` | **Replay-protection nonces commit in batches for throughput.** src/server/request_replay.rs commits replay-protection nonces in batched or group-commit fashion, or maintains a bounded in-memory window backed by a durable epoch, so per-request durable-commit overhead no longer dominates every served request's latency while replay protection is not weakened. | A benchmark measures served request throughput before and after the change at matching concurrency and confirms an improvement with no regression in a replay-attack negative test. |
| `EG-REPO-INGEST-R006` | **Native ingestion commits fast; heavy enrichment deferred.** Indexing a repository or other source completes natively within seconds: parsing, symbol resolution, and statistical analysis run inside EG as batched durable commits, while classical ML, embeddings, and LLM-based enrichment never block the commit and are instead enqueued as durable, budgeted work items with an admission verdict, drained by background workers, plus bounded on-demand enrichment when a query needs it. | An end-to-end benchmark against real public repositories records commit latency for the native stages and confirms the deferred-enrichment work items are admitted, enqueued, and completed asynchronously without blocking the index commit. |
| `EG-REPO-INGEST-R007` | **Large ingestion batches refuse atomically with a stable code.** SourceIngest refuses an over-limit batch atomically with a stable REPOSITORY_BATCH_TOO_LARGE-class error code before any graph mutation, and a large-batch regression test exercises this refusal path. | A regression test submits a batch past the configured limit and confirms the atomic refusal, the stable error code, and that no partial graph mutation occurred. |
| `EG-REPO-INGEST-R008` | **Oversized batches return a stable code for retry.** When a repository batch exceeds the 64 MiB write-byte ceiling, EG refuses it with the stable REPOSITORY_BATCH_TOO_LARGE error code and enough bounded detail that the connector SDK's halve-and-resend logic can split and retry the batch, rather than a generic internal error. | An integration test submits a batch above the 64 MiB ceiling and confirms the stable error code and that a halve-and-resend retry using that code succeeds. |
| `EG-REPO-INGEST-R009` | **Repository hydration links into the specification bridge.** EG's repository hydration maps indexed repository entities into the semantic bridge that links them to their source, test, specification, and release relationships, so a query can follow from a hydrated code entity to its governing specification without a duplicate graph writer. | An integration test hydrates a sample repository and confirms its entities are reachable through the documented source-to-specification relationship chain. |
| `EG-REPO-INGEST-R010` | **Tree-sitter grammar coverage expands to 18 more languages.** EG's native parser (parser/tree_sitter.rs) adds tree-sitter grammar support for Swift, Kotlin, Objective-C, Zig, Julia, Elixir, Groovy, PowerShell, Fortran, Pascal, Verilog, CUDA, HTML, CSS, JSON, Terraform/HCL, and DreamMaker, alongside its existing C, C++, C#, Go, Rust, Python, JavaScript, TypeScript, React, Java, Scala, Ruby, PHP, Lua, Bash, and SQL support; DreamMaker, lacking a maintained tree-sitter grammar, uses a custom extractor. | A grammar-expansion test suite parses a representative fixture for each newly added language and confirms a successful parse outcome for each. |
| `EG-REPO-INGEST-R011` | **Ingestion community detection uses pure Leiden.** EG's ingestion community detection uses pure Leiden partitioning via the shared driver in graph_algos/leiden.rs, wired through algorithms.rs and features.py, not a Louvain/Leiden hybrid, because Louvain alone can produce badly connected or fully disconnected communities that would otherwise be trusted as valid modules. | A community-detection test confirms ingestion's partitioning path invokes Leiden's refinement phase and that no committed community in a test graph is internally disconnected. |
