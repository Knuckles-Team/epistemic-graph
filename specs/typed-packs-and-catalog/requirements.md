# EG-TYPED-PACKS requirements

| ID | Requirement | Verification |
|---|---|---|
| `EG-TYPED-PACKS-R001` | **Connector pack contract types and golden digest vectors.** EG defines the typed ConnectorPackIndex, entry, section and annotation types together with the ConnectorPackOp and AgentComponent.Content operations, and computes framed SHA-256 digests exactly as recorded in the golden vectors at contract/fixtures/connector_pack_digest_vectors.json. All generated clients share this one wire contract. | Contract and unit tests assert that digest computation over the sample fixtures matches the published golden vectors byte-for-byte. |
| `EG-TYPED-PACKS-R002` | **Engine-owned body storage with guarded refcounts and reconciliation.** EG stages engine-owned component bodies in content-addressed storage with guarded holder-row refcounts, keyed by SHA-256, and serves verified body bytes through the AgentComponent.Content method; a body with no holder is reclaimed by a reconciler only after its grace window expires. | Integration tests cover body staging and holder refcount updates across unchanged, revised and withdrawn components, plus a fault test for orphan reclamation after the grace window. |
| `EG-TYPED-PACKS-R003` | **Import boundary enforces archive integrity, importer binding and G1-G21.** EG's ConnectorPack.Import handler verifies archive length and digest. It checks the submitted request against the bound importer. It applies validation rules G1 through G21 from architecture.md. It keeps ConnectorPack and the agent-layer write methods LocalOnly until a separately specified clustered writer exists. | Integration and negative tests exercise the Import boundary across each G1-G21 refusal path and an importer-binding mismatch. They confirm zero catalog mutation on any rejection. |
| `EG-TYPED-PACKS-R004` | **Python ConnectorPackClient with a deterministic import key.** The epistemic_graph Python package provides a ConnectorPackClient that computes a deterministic import idempotency key independent of any per-request identifier, so retrying after a lost reply reuses the exact same import operation key instead of creating a duplicate import. | Unit tests assert that retrying after a simulated transport loss reuses the identical generated idempotency key and that the client only consumes generated wire types for status, content and import results. |
| `EG-TYPED-PACKS-R005` | **Acceptance suite for pack mutation, crash, authorization and tenancy.** EG's test suite includes a planted-invalid-input mutation test for each validation rule, crash and retry tests over the Import atomic commit path, content-model, authorization, tenancy and clustered-mode tests, and at least one end-to-end connector fixture exercising import through to a served read. | The mapped test suite in test-spec.md passes, combining mutation, crash/retry, tenancy and end-to-end fixture coverage. |
| `EG-TYPED-PACKS-R006` | **Outbox-driven pack projection with a visibility readiness gate.** An Agent Library outbox consumer projects the current committed pack head into its reserved graph, attaches the resulting schema source, and marks the record visible only through a compare-and-swap visibility write; typed catalog and component reads exclude any record that has not passed this gate, and an administrator can invoke Reproject to re-drive a failed or stale projection without losing later work. | Integration tests cover projection commit ordering, the visibility compare-and-swap, read-path filtering of unready records, and a forced Reproject after a simulated failure. |
| `EG-TYPED-PACKS-R007` | **Admin-controlled pack importer binding and entry retirement.** EG's Bind, Unbind and Retire operations require the admin:connector-pack capability, let an administrator change the authorized importer and permanently retire a pack entry, and refuse a later import that attempts to reintroduce a retired entry with a stable RETIRED_ENTRY_RETURNED error. | Authorization and negative tests confirm Bind, Unbind and Retire are refused without admin:connector-pack and that reintroducing a retired entry returns RETIRED_ENTRY_RETURNED without mutating the head. |
| `EG-TYPED-PACKS-R008` | **Blob content-addressed store garbage-collection hardening.** EG's blob store reseeds cursor identifiers safely, computes an accurate live set during garbage collection, expires abandoned uploads, enforces a grace period before reclaiming unreferenced bodies, and applies holder-row refcount updates idempotently so repeated writes never over- or under-count references. | The blob store test suite covers grace-period reclamation, garbage-collection live-set correctness, cursor reseeding and idempotent holder-refcount updates. |
| `EG-TYPED-PACKS-R009` | **Projection readiness gates reader visibility.** A reader never observes a pack record as available until its projection into the graph has completed and been marked visible; a committed catalog write by itself is not sufficient for visibility. | Integration tests confirm a committed-but-unprojected record is excluded from catalog and component reads until the visibility marker is set. |
| `EG-TYPED-PACKS-R010` | **Import is a single atomic operation, not a staged protocol.** ConnectorPack import validates, stages and commits a pack through one Import operation. EG does not expose separate Prepare, Commit or Abort steps for pack admission. | Contract tests confirm ConnectorPackOp exposes only the single Import method for pack admission, with no prepare, commit or abort variants. |
| `EG-TYPED-PACKS-R011` | **Incompatible Agent Library storage is refused, not upgraded.** When EG finds an existing Agent Library store in a format it does not recognize, it refuses to open it with a named AGENT_LIBRARY_FORMAT_UPGRADE_REQUIRED error instead of reading or migrating it, and no version performs an automatic offline upgrade of that layout. | A negative test opens an incompatible store and asserts the exact AGENT_LIBRARY_FORMAT_UPGRADE_REQUIRED refusal with no partial read or write. |
| `EG-TYPED-PACKS-R012` | **Pack and agent-layer write methods are local-only in clustered mode.** ConnectorPack and its four agent-layer write methods are declared LocalOnly and refuse to execute in clustered mode until a separately specified clustered writer exists; a method-inventory test enumerates exactly this set. | An inventory test asserts the exact set of methods marked LocalOnly, and a clustered-mode integration test confirms each one is refused. |
| `EG-TYPED-PACKS-R013` | **Capability IRI validation distinguishes native errors from claims.** EG rejects a capability or modality IRI that misuses the native eg: namespace, while accepting a well-formed foreign-namespace absolute IRI as a recorded claim rather than a verified native fact; extending the native vocabulary follows a governed process. | Validation tests cover a mistyped native IRI refusal, a foreign-namespace IRI accepted as a claim, and a malformed IRI refusal. |
| `EG-TYPED-PACKS-R014` | **Absent entries become reversible Withdrawn, not retired.** When a reimported pack omits a previously published entry, EG sets that component's lifecycle to Withdrawn. A later import of the same entry restores it. EG does not retire it permanently. | An integration test removes then restores an entry across two imports. It asserts the entry becomes Withdrawn and later republishes under the same ID. |
| `EG-TYPED-PACKS-R015` | **Importer authority is admin-bound, with environment value as bootstrap only.** Source authorization for pack import is governed by an admin-bound importer identity; an environment-configured importer value is honored only as the initial bootstrap default before an administrator binds one explicitly. | A test confirms the environment-configured importer is used only before any admin Bind call and is superseded once an administrator binds a different importer. |
| `EG-TYPED-PACKS-R016` | **Server pin follows declared contract, not package version.** The pack's server-entry pin binds the declared contract version together with the server's name and instructions; package version is recorded as provenance only and never determines pin equality or compatibility. | A unit test confirms two entries differing only in package version compare as pin-equal, while a change to declared contract version, name or instructions produces a new pin. |
| `EG-TYPED-PACKS-R017` | **Release scope excludes an offline Agent Library upgrade path.** The delivered typed-pack and catalog capability covers the full design described in this specification except an offline upgrade path for an existing incompatible Agent Library store, which remains explicitly out of scope. | The specification's success criteria and the test-spec.md mapping are checked to confirm no offline-upgrade test is required for acceptance. |
| `EG-TYPED-PACKS-R018` | **Body reads use AgentComponent.Content, not a pack-specific method.** Verified component body bytes are read exclusively through the existing AgentComponent.Content method. EG does not expose a separate ConnectorPack-specific body-read operation. | A contract inventory test confirms ConnectorPackOp has no body-read variant and that AgentComponent.Content serves pack-sourced body bytes. |
| `EG-TYPED-PACKS-R019` | **Only SKILL.md is imported as skill content.** Importing a skill entry admits only the SKILL.md file itself as skill content; any files a skill references for support are deferred to a separately specified bounded contract and are not imported. | A validation test confirms a skill entry with supporting-file references imports only SKILL.md and that those references do not cause an import failure or get stored as body content. |
