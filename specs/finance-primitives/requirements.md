# EG-FINANCE-PRIMITIVES requirements

| ID | Requirement | Verification |
|---|---|---|
| `EG-FINANCE-PRIMITIVES-R001` | **Cross-host BacktestRun digest and Pine parity for finance-core.** The BacktestRun content digest is canonical across supported host architectures by normalizing serialization, floating-point and timestamp inputs before hashing. A Pine companion script for the SuperTrend and ATR kernels produces the same signal transitions as the Rust implementation from a shared checked-in bar fixture and parameter version, and finance-specific classes are folded into one finance-v1 ontology with duplicate class definitions removed. | Independent builds on two architectures are compared for equal digests, and a parity fixture test asserts the Pine and Rust implementations produce identical signal transitions. |
| `EG-FINANCE-PRIMITIVES-R002` | **Rehome generic finance evaluation kernels into eg-numeric.** Rolling z-score, EWMA, information coefficient and ratio, effective sample size, Diebold-Mariano, deflated Sharpe, purged combinatorial cross-validation, probability of backtest overfitting, Brier, Kalman, Ornstein-Uhlenbeck, ADF and regime HMM calculations are owned by eg-numeric evaluation and calibration modules and are callable as UQL time-series functions. Finance-specific method wrappers are removed or remain only as thin documented aliases over the shared kernels, with callers migrated to the generic surface and generated method counts reconciled in one change. A regime derivation that requires an unbounded prefix refit declares a bound or refuses with a typed state-budget error rather than reporting an unverified result. | Unit tests cover each relocated kernel, and a method-count reconciliation check confirms the generated inventory matches client bindings with no duplicate implementation remaining. |
| `EG-FINANCE-PRIMITIVES-R003` | **Compute PBO from a BacktestRun's own CSCV splits.** Probability of backtest overfitting is computed from a BacktestRun's own combinatorial symmetric cross-validation splits rather than a separate caller-supplied summary of performance rows. For each split the implementation selects the top in-sample candidate by a deterministic tie rule, ranks its out-of-sample performance against all candidates, and counts it as overfit only when strictly below the exact median, treating equality to the median as not overfit. | A skilled-strategy fixture and an overfit-strategy fixture each assert the expected PBO value computed directly from the record's own split matrix. |
| `EG-FINANCE-PRIMITIVES-R004` | **finance-v1 asset, account, and strategy record types.** finance-v1 defines validated asset classes for equity, ETF, fund, index, FX pair, commodity spot and future with contract spec, crypto, real-estate holding, and cash, along with Account, Activity, Lot, Position, PortfolioGroup with Basic and Holdings views, StrategySpec, StrategyRun, and LeverageTerms record types. Delivered as child requirements, one per code root, producer first: `EG-FINANCE-PRIMITIVES-R004.1` (ontology/SHACL asset-class vocabulary), `.2` (the Rust record types), `.3` (server wiring and contract regeneration). This row becomes LANDED when every child is LANDED. | Ontology and SHACL schema validation tests confirm each record type enforces its required fields, links, and controlled vocabulary. |
| `EG-FINANCE-PRIMITIVES-R004.1` | **finance-v1 asset-class controlled vocabulary.** The `:assetClass` SHACL shape accepts the canonical `equity`, `etf`, `fund`, `index`, `fx_pair`, `commodity_spot`, `commodity_future`, `crypto`, `real_estate` and `cash` values, plus the deprecated migration aliases `stock`, `forex` and `commodity` preserved from the prior vocabulary. Code root: `crates/eg-core/ontology/finance-v1.ttl` and `finance-v1.shapes.ttl`. | SHACL validation tests assert every canonical and legacy alias value conforms and an unlisted value (for example `bond`) is refused. |
| `EG-FINANCE-PRIMITIVES-R004.2` | **finance-v1 Account/Activity/Lot/Position/PortfolioGroup/StrategySpec/StrategyRun/LeverageTerms Rust record types.** Delivered as child requirements, one per record-type group, producer first: `EG-FINANCE-PRIMITIVES-R004.2.1` (the `Account` and `Position` OWL classes and SHACL shapes), `.2.2` (`Activity` and `Lot`), further children for `PortfolioGroup`, `StrategySpec`, `StrategyRun` and `LeverageTerms`. This row becomes LANDED when every child is LANDED. | Ontology and SHACL schema validation tests confirm each record type enforces its required fields, links, and controlled vocabulary. |
| `EG-FINANCE-PRIMITIVES-R004.2.1` | **Account and Position OWL classes and SHACL shapes.** finance-v1 defines `:Account` (a portfolio owner's brokerage/custodial account: `accountId`, `baseCurrency`, closed-vocabulary `accountKind`) and `:Position` (an account's signed holding of one instrument under one cost-basis method: `positionAccount`, `positionInstrument`, `positionQuantity`, closed-vocabulary `costBasisMethod`), distinct from the pre-existing exchange-execution `:PortfolioPosition`. Code root: `crates/eg-core/ontology/finance-v1.ttl` and `finance-v1.shapes.ttl`. | SHACL validation tests assert required fields/links are enforced and each closed vocabulary (`accountKind`, `costBasisMethod`) refuses an unlisted value. |
| `EG-FINANCE-PRIMITIVES-R004.2.2` | **Activity and Lot OWL classes and SHACL shapes.** finance-v1 defines `:Activity` (a point-in-time ledger event against a position: buy, sell, dividend, transfer, split, fee) and `:Lot` (one FIFO/LIFO/specific-lot cost-basis parcel opened by an acquiring activity). Code root: `crates/eg-core/ontology/finance-v1.ttl` and `finance-v1.shapes.ttl`. | SHACL validation tests assert required fields/links are enforced and each closed vocabulary value is checked. |
| `EG-FINANCE-PRIMITIVES-R004.3` | **finance-v1 record-type server wiring and contract regeneration.** The R004.2 record types are wired into server handlers and the generated contract/client surfaces are regenerated to carry them. Code root: `src/server/`, `contract/`, generated clients. | A handler test reads/writes each record type through its entry point, and the contract-freshness check passes with the regenerated artifacts committed. |
| `EG-FINANCE-PRIMITIVES-R005` | **Deterministic fixed-point portfolio accounting.** Portfolio accounting uses fixed-point arithmetic for lot and cost-basis tracking under FIFO, LIFO, specific-lot, and average-cost elections, and derives realized and unrealized profit and loss, time-weighted return, money-weighted return and XIRR, dividend handling, multi-currency conversion at trade and valuation dates, and benchmark comparison. | Deterministic unit and golden fixture tests reproduce byte-identical results across replays of the same ordered inputs. |
| `EG-FINANCE-PRIMITIVES-R004` | **finance-v1 asset, account, and strategy record types.** finance-v1 defines validated asset classes for equity, ETF, fund, index, FX pair, commodity spot and future with contract spec, crypto, real-estate holding, and cash, along with Account, Activity, Lot, Position, PortfolioGroup with Basic and Holdings views, StrategySpec, StrategyRun, and LeverageTerms record types. | Ontology and SHACL schema validation tests confirm each record type enforces its required fields, links, and controlled vocabulary. |
| `EG-FINANCE-PRIMITIVES-R005` | **Deterministic fixed-point portfolio accounting.** Portfolio accounting uses fixed-point arithmetic for lot and cost-basis tracking under FIFO, LIFO, specific-lot, and average-cost elections, and derives realized and unrealized profit and loss, time-weighted return, money-weighted return and XIRR, dividend handling, multi-currency conversion at trade and valuation dates, and benchmark comparison. Delivered as child requirements, producer first: `EG-FINANCE-PRIMITIVES-R005.1` (the FIFO/LIFO fixed-point lot-matching engine), `.2` (specific-lot/average-cost elections and transfer/split invariants), further children for P&L/TWR/XIRR/FX/benchmark. This row becomes LANDED when every child is LANDED. | Deterministic unit and golden fixture tests reproduce byte-identical results across replays of the same ordered inputs. |
| `EG-FINANCE-PRIMITIVES-R005.1` | **FIFO/LIFO fixed-point lot-matching engine.** A pure function over an ordered slice of signed fixed-point buy/sell activities matches sells to open lots under FIFO or LIFO, refusing non-positive quantity/price, out-of-order sequence, and oversold quantity. Code root: `crates/eg-compute/src/finance/lot_accounting.rs`. | Unit tests assert FIFO/LIFO matching order, each refusal, and that replaying the same ordered activities is byte-identical. |
| `EG-FINANCE-PRIMITIVES-R006` | **Point-in-time corporate actions and exchange session calendars.** Corporate actions, including splits, dividends, symbol changes, and delistings, are recorded as point-in-time facts, and exchange calendars model regular, pre-market, and post-market sessions. Every price result carries the session in which it was observed. | Golden fixtures covering corporate-action and session-boundary cases assert correct point-in-time resolution and session tagging. |
| `EG-FINANCE-PRIMITIVES-R007` | **Versioned StrategySpec evaluator with DCA, trend, rebalancing.** A versioned, typed StrategySpec is evaluated deterministically and ships default strategies for dollar-cost averaging by fixed amount, by shares, or by value-averaging target, trend following using moving-average and trend-flip signals, and calendar- or threshold-based rebalancing. Evaluation emits proposed actions only and never places or authorizes an order. | Deterministic unit tests exercise each default strategy's proposed-action output against fixed input fixtures. |
| `EG-FINANCE-PRIMITIVES-R008` | **Strategy backtests sealed through BacktestRun.** Strategy backtests are sealed as BacktestRun records that mandate purged combinatorial cross-validation, deflated Sharpe, probability of backtest overfitting, and transaction costs, and support standard comparisons of dollar-cost averaging, lump-sum, and trend strategies over the same point-in-time universe. | Integration tests seal a BacktestRun for each compared strategy and assert the mandatory validation fields are present and mutually consistent. |
| `EG-FINANCE-PRIMITIVES-R009` | **Calibrated abstaining recommendations with scorecards.** Each holding or watchlist item receives a calibrated recommendation of accumulate, hold, de-risk, or abstain, citing the strategy version and supporting evidence, and per-strategy scorecards compare prior recommendations against later outcomes. Recommendations are sealed as informational-only AnalysisSnapshot records that authorize no order. | Unit tests assert that insufficient-evidence conditions produce an abstain result and that a non-abstaining recommendation cites its strategy version and evidence. |
| `EG-FINANCE-PRIMITIVES-R010` | **Leverage risk module with margin, sizing, live-order boundary.** The leverage module models Reg T margin, futures contract specs, leveraged-ETF daily-reset decay, and US FX limits, and simulates margin calls, liquidation, position sizing, and risk of ruin. Analysis defaults to paper mode; a live leveraged order requires a per-instrument policy and designated approvers, and CFDs are flagged unavailable for US retail accounts. | Scenario-based unit tests assert margin-call and liquidation simulation results and confirm live-order eligibility is refused without a matching policy and approver. |
| `EG-FINANCE-PRIMITIVES-R011` | **Finance alerts published through the finance outbox.** Price, trend-flip, DCA-due, and margin-threshold alerts are published as finance events through the outbox topic family for delivery by existing channels. | Integration tests assert each alert condition produces the correct typed event on the outbox and that delivery is idempotent on replay. |
| `EG-FINANCE-PRIMITIVES-R012` | **Optional one-way Ghostfolio activity import.** An optional Ghostfolio instance on the shared Postgres database attaches through the typed source registry, and a one-way mapper converts its activities into finance-v1 records without EG writing back into Ghostfolio's own schema. | Integration tests against a disposable Ghostfolio fixture assert idempotent, one-way import of activities into finance-v1. |
| `EG-FINANCE-PRIMITIVES-R013` | **Golden accounting and risk fixtures with full provenance.** Finance golden fixtures cover broker statements, corporate actions, daylight-saving and session boundaries, leveraged-ETF decay against published returns, and futures rolls, using fixed-point arithmetic with no floating-point money. Every displayed figure carries its source, as-of time, and session. | Golden fixture tests compare computed results against published reference values and assert the source, as-of, and session provenance fields are present on every output. |
| `EG-FINANCE-PRIMITIVES-R014` | **finance-v1 thin instrument and signal module.** finance-v1 defines a thin module of Instrument, Listing, Venue, BarSeries, IndicatorSpec, SignalState, TrendFlip, and MacroEvent types aligned to the FIBO ontology. | Schema validation tests confirm each type's required fields and its alignment to the FIBO ontology. |
| `EG-FINANCE-PRIMITIVES-R015` | **AnalysisSnapshot records with share.read control leases.** AnalysisSnapshot records capture informational analysis output together with a share.read control-lease link for access control, and each snapshot carries a notice marking the output as informational-only. | Unit tests assert a sealed AnalysisSnapshot includes its control-lease link and informational-only notice. |
| `EG-FINANCE-PRIMITIVES-R016` | **Incremental deterministic indicator kernels with Pine parity.** Indicator kernels for ATR, SuperTrend, SMA and EMA, 200-week SMA, the 20/21 band, and Heikin-Ashi are computed incrementally and deterministically, with Pine parity fixtures proving the reference implementation matches. | Parity fixture tests compare each kernel's output against the Pine reference implementation on shared bar data. |
| `EG-FINANCE-PRIMITIVES-R017` | **BacktestRun provenance record with mandatory fields.** A BacktestRun record captures full provenance for a backtest, including mandatory purged combinatorial cross-validation, deflated Sharpe, probability of backtest overfitting, transaction costs, the fill rule, the point-in-time universe, and a no-look-ahead check. | Unit tests assert sealing a BacktestRun without any mandatory field is refused and that a valid record passes the no-look-ahead check. |
