# MEDULLA-SDLC — Requirements

Governing spec: [spec.md](spec.md).

Each row is one requirement. A child row `.n` is one five-minute unit of work. A row names the file it touches and the test that proves it. The generator sets each row's state in `status.json`.

| ID | Requirement | Acceptance |
|---|---|---|
| `MEDULLA-SDLC-R001` | **Lifecycle record vocabulary and derived edges (rollup).** The engine must hold the nine lifecycle record kinds and the closed edge set of plan.md. Named rules derive the edges from the changeset log and the code graph. Children `.1` to `.6` deliver it. | See each child. |

Add one SHACL shape per edge with its domain and range. | `crates/eg-core/tests/lifecycle_vocab.rs::edge_set_is_closed_and_shaped` loads the ontology and validates one fixture per edge. |
| `MEDULLA-SDLC-R001.2` | **Behavior.** Add `derive_lifecycle_edges(changeset, code_graph) -> Vec<DerivedEdge>` in `crates/eg-core/src/lifecycle/derive.rs`. It applies the eight named rules of plan.md. Each `DerivedEdge` carries the rule name, the rule version and the input digests. The function is deterministic. | `crates/eg-core/tests/lifecycle_derive.rs::rules_emit_expected_edges` applies each rule to a fixture and compares the output. |
| `MEDULLA-SDLC-R001.3` | **Wiring.** The MEDULLA-SCM-R006 re-index hook calls `derive_lifecycle_edges` after each accepted changeset. `IndexRepository` at `src/server/dispatch/router/source_ingest.rs:24` calls it for each ingested git commit. No other caller writes these edges. | `tests/test_sdlc_derive_served.py::test_accept_writes_derived_edges` submits a changeset and reads the derived edges back. |
| `MEDULLA-SDLC-R001.4` | **Refusal.** A direct write of a derived edge kind must refuse with `LIFECYCLE_EDGE_DERIVED_ONLY`. A derived edge with an absent endpoint must refuse with `LIFECYCLE_ENDPOINT_UNKNOWN`. A refusal writes nothing. | `crates/eg-core/tests/lifecycle_derive.rs::manual_edge_write_is_refused` asserts both codes and an unchanged graph. |
| `MEDULLA-SDLC-R001.5` | **Evidence.** A rebuild replays every rule over the changeset log. The rebuilt edge set must equal the incremental edge set byte for byte. | `crates/eg-core/tests/lifecycle_derive.rs::rebuild_equals_incremental` applies 200 changesets incrementally and compares a rebuild. |
| `MEDULLA-SDLC-R001.6` | **Hot-path proof.** The entry point is the served `SubmitChangeset`. Peak memory stays under 64 MiB. | `cargo bench --bench lifecycle_derive` against the stored baseline fails on a 10 percent regression. |
| `MEDULLA-SDLC-R002` | **Release and deployment records (rollup).** The engine must store releases and deployments. It links each deployment to a release by artifact digest. Children `.1` to `.6` deliver it. | See each child. |

The `contains.release_range` rule links a release to the changesets after the previous release head. | `crates/eg-types/tests/lifecycle_records.rs::unknown_digest_stays_unattributed` records a deployment with an unknown digest. |
| `MEDULLA-SDLC-R002.3` | **Wiring.** Add the served methods `RecordRelease` and `RecordDeployment` in `src/server/handlers/lifecycle.rs`. | `MEDULLA-SDLC-R003` | **Defect records and intake (rollup).** The engine must store defects and accept them from five intake paths. It removes duplicates by a signature digest. Children `.1` to `.6` deliver it. | See each child. |
| `MEDULLA-SDLC-R003.1` | **Model.** Add `Defect{id, repo, title, intake, signature_digest, severity, status, symptoms, created_at}` in `crates/eg-types/src/lifecycle.rs`. `intake` is a closed set: `gate_failure`, `run_failure`, `incident`, `connector_issue`, `direct`. `status` is a closed set: `new`, `triaged`, `fixing`, `fixed`, `verified`, `closed`, `rejected`. | `crates/eg-types/tests/lifecycle_records.rs::defect_round_trips` round-trips a defect and refuses an unknown status. |
| `MEDULLA-SDLC-R003.2` | **Behavior.** `FileDefect` normalizes the symptom: it strips addresses, line numbers and temporary paths. It hashes the result to the signature digest. An open defect with the same signature absorbs the symptom. A closed defect with the same signature reopens. | `crates/eg-core/tests/defect_intake.rs::same_signature_reuses_open_defect` files two equal symptoms and observes one defect. |
| `MEDULLA-SDLC-R003.3` | **Wiring.** `RecordGateVerdict` of MEDULLA-SCM-R008 calls `FileDefect` on a fail verdict. The run-trace writer of MEDULLA-ORCH-VOCAB-R009 calls it on a failed run outcome. `incident.correlate` of MEDULLA-UNIFIED-DATA-PLANE-R760 calls it when an incident names a code symbol. | `tests/test_sdlc_defect_served.py::test_failed_gate_opens_defect` records a fail verdict and reads the defect back. |
| `MEDULLA-SDLC-R003.4` | **Refusal.** A status move that skips a state must refuse with `DEFECT_TRANSITION_ILLEGAL`. A move to `verified` must refuse with `DEFECT_UNVERIFIED` unless a bound test passes on the fix changeset. | `tests/test_sdlc_defect_served.py::test_illegal_transitions_refuse` asserts both codes. |
| `MEDULLA-SDLC-R003.5` | **Evidence.** Each defect lists its symptoms with the intake path, the source record id and the time. A readback through a separate principal must equal the stored list. | `tests/test_sdlc_defect_served.py::test_symptom_evidence_reads_back` compares every field. |
| `MEDULLA-SDLC-R003.6` | **Hot-path proof.** The entry point is the served `RecordGateVerdict`. The benchmark `benches/defect_intake.rs` files 100,000 symptoms over 1,000 signatures. The p99 per symptom stays under 1 ms. | `cargo bench --bench defect_intake` against the stored baseline fails on a 10 percent regression. |
