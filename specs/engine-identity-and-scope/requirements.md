# EG-IDENTITY requirements

| ID | Requirement | Verification |
|---|---|---|
| `EG-IDENTITY-R001` | **Multi-issuer OIDC trust list with per-issuer kind limits.** EG's primary OIDC verifier (src/server/oidc.rs, src/server/auth.rs) maintains an explicit, ordered multi-issuer trust list of issuer, JWKS source, audience, and allowed-principal-kind entries, accepts an overlapping rotated key only during a declared window, and restricts principal kind per issuer so a Keycloak-backed issuer can authenticate service principals only. | A negative test asserts an unknown, ambiguous, or disallowed-kind issuer fails verification before method dispatch, and a positive test confirms a rotated key is accepted only within its declared overlap window. |
| `EG-IDENTITY-R002` | **Identity and RBAC writes recompute roles and audit atomically.** Every identity or RBAC mutation in EG (security.rs, identity_admin.rs) recomputes the complete effective role set within the same durable transaction as the write, and src/audit.rs records an allow or denial entry naming the actor, tenant, operation, target, and authorization digest change, including a bounded sample of denied attempts. | A restart/fault test confirms a failed persistence rolls back the role change and its audit entry together, and a tamper-detection check catches a reordered or altered identity audit record. |
| `EG-IDENTITY-R003` | **Identity mode is a durable singleton with CAS transition.** EG stores identity mode (none, local, or external) as a durable singleton with a monotonic epoch, transitions it only via compare-and-set once a new identity_config component validates the documented preconditions for that transition, and invalidates every active authentication token and rotates issuer material after the commit while retaining accounts, links, grants, and data. | A fault-injection test confirms a stale epoch, missing surviving admin, or unmet precondition returns a typed refusal with no mode or data change, and an integration test confirms tokens are invalidated only after the transition commits. |
| `EG-IDENTITY-R004` | **Generated scope registry classifies every capability scope.** EG publishes a single generated, versioned scope registry from crates/eg-capabilities capability declarations, classifying each scope as user, domain, service-only, approver, or admin, with the generated package catalog and server checks sharing the same digest. | A generation check confirms the published scope registry digest matches the server's own classification for every declared scope, and a negative test confirms an unclassified or wildcard scope fails generation. |
| `EG-IDENTITY-R005` | **Semantic workers use one identity across queue classes.** A production semantic worker presents a single verified identity consistently across every queue class it processes, rather than switching principals per class, so authorization and audit records for its work remain attributable to one principal. | `dispatch_attributes_every_queue_class_to_the_one_verified_principal` verifies principal attribution. `semantic_owner_registry_is_scoped_to_persistence_root` checks root isolation and canonical alias reuse in `src/server/semantic_index.rs`. |
| `EG-IDENTITY-R006` | **Tenant roles read the shared commons graph.** `IsolationLayer::provision_tenant_graph_access` (crates/eg-core/src/isolation/policy_admin.rs) grants the `tenant:<slug>` role Read on the exact `__commons__` graph, beside its tenant-pattern Read and Write grants. | A unit test confirms a tenant member reads `__commons__`, cannot write it, and cannot read another tenant's graph. The idempotence test confirms three grants after repeated provisioning. |
| `EG-IDENTITY-R007` | **Scopes `identity:admin`, `loops:read` and `loops:control` are registered in the engine contract.** `contract/scopes.json` (and its `epistemic_graph/contract` mirror) registers `identity:admin` (class admin), `loops:read` (user) and `loops:control` (domain), generated from `crates/eg-capabilities/src/scopes.rs`. Unblocks graph-os GRAPHOS-OPS-R014 identity operations and GRAPHOS-OPS-R022.2.1. | The R004 generation check passes with the three scopes present and a negative test shows an unregistered scope still fails generation. |
| `EG-IDENTITY-R008` | **Run scope comes from a durable policy node, never from plan text (rollup).** The engine must bound a run's tool and data scope by a stored policy node. A model-written plan must never widen that bound. | Test: `crates/eg-core/tests/scope_bound.rs::plan_cannot_widen_policy_bound` |
| `EG-IDENTITY-R008.1` | **Locate and wire the attach point.** The implementer must find where a plan's tool set is admitted beside `crates/eg-core/src/isolation/policy_admin.rs` and record `file:line` in `plan.md`. | Test: `crates/eg-core/tests/scope_bound.rs::attach_point_is_reached` |
| `EG-IDENTITY-R008.2` | **Typed `ScopeBound`.** Add `ScopeBound { policy_iri, allowed_tools, allowed_graphs }` to `crates/eg-core/src/isolation/scope_bound.rs`. The type must reject an empty `policy_iri`. | Test: `crates/eg-core/src/isolation/scope_bound.rs::tests::empty_policy_iri_is_refused` |
| `EG-IDENTITY-R008.3` | **Pure subset check.** Add `scope_within_bound(plan_tools, bound)` to `scope_bound.rs`. It must return the first out-of-bound tool IRI, not a boolean. | Test: `crates/eg-core/src/isolation/scope_bound.rs::tests::first_excess_tool_is_named` |
| `EG-IDENTITY-R008.4` | **Bound is read from the stored policy node.** The loader must read `ScopeBound` from the principal's policy node in the graph. It must ignore any scope field carried in the plan body. | Test: `crates/eg-core/tests/scope_bound.rs::plan_scope_field_is_ignored` |
| `EG-IDENTITY-R008.5` | **Typed refusal `ScopeExceedsPolicy`.** The admission path must refuse an out-of-bound plan with `ScopeExceedsPolicy` naming the tool IRI and policy IRI. It must write an audit record. | Test: `crates/eg-core/tests/scope_bound.rs::excess_plan_is_refused_and_audited` |
| `EG-IDENTITY-R008.6` | **End-to-end proof over the wire.** A served test must submit a plan that names a tool outside the principal's policy and assert `ScopeExceedsPolicy`. A second plan inside the bound must pass. | Test: `tests/identity/test_scope_bound_served.py::test_plan_scope_is_bounded_by_policy` |
