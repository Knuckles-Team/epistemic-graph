| `MEDULLA-IDENTITY-R001` | **Multi-issuer OIDC trust list with per-issuer kind limits.** The verifier in `src/server/oidc.rs` and `src/server/auth.rs` keeps an ordered multi-issuer trust list. Each entry holds issuer, JWKS source, audience and allowed principal kind. An overlapping rotated key is accepted only during a declared window. Principal kind is restricted per issuer. An external identity-provider issuer can authenticate service principals only. The arbora issuer is an entry of this list with the service-only kind. | A negative test asserts that an unknown, ambiguous or disallowed-kind issuer fails verification before method dispatch. A positive test confirms a rotated key is accepted only within its declared overlap window. |
| `MEDULLA-IDENTITY-R002` | **Identity and RBAC writes recompute roles and audit atomically.** Every identity or RBAC mutation in Medulla (security.rs, identity_admin.rs) recomputes the complete effective role set within the same durable transaction as the write, and crates/medulla-kernel/src/audit.rs records an allow or denial entry naming the actor, tenant, operation, target, and authorization digest change, including a bounded sample of denied attempts. | A restart/fault test confirms a failed persistence rolls back the role change and its audit entry together, and a tamper-detection check catches a reordered or altered identity audit record. |
| `MEDULLA-IDENTITY-R003` | **Identity mode is a durable singleton with a compare-and-set transition (rollup).** Stage: identity and placement, request boundary. Medulla stores the identity mode (`none`, `local` or `external`) as a durable singleton with a monotonic epoch. A transition commits only through compare-and-set on the epoch after the `identity_config` component validates the preconditions. The commit invalidates every session issued under an older epoch and rotates the issuer material. Accounts, links, grants and data stay. `none` is the isolated anonymous store of R003.1. Conversion into or out of it is an offline operator command, never a served method. `ARBORA-IDENTITY-R014` is the consumer that exercises a full round trip. Arbora calls `UserOp::Create` to register, `CredentialOp::ChangePassword` to change a password and `TokenOp::IssuePasswordReset` to reset it. `MEDULLA-IDENTITY-R707` defines these operations. Children `.1` to `.3` exist; children `.4` to `.8` deliver the transition. Depends on: `MEDULLA-IDENTITY-R002`. | Root journey: `tests/identity/test_identity_mode_served.py::test_local_external_round_trip` (L4). |
| `MEDULLA-IDENTITY-R003.1` | **Explicit isolated anonymous store authority (native TCP qualification).** Medulla consumes Arbora's explicit local `none` admission through `--auth-mode none` / `GRAPH_SERVICE_AUTH_MODE=none`. This mode requires no secret and either private UDS or literal loopback native TCP. It rejects auxiliary listeners and cluster configuration. The durable store must be fresh or already anonymous-marked. Default authenticated startup remains unchanged and refuses anonymous stores. A distinct server-owned origin supplies anonymous authority. It fixes principal `anonymous`, tenant `local` and policy `no-auth`, without credentials or signed request envelopes. Caller claims cannot substitute identity. The engine refuses mismatched embedded authority with the existing typed `ACCESS_DENIED` code. Existing ACL and mutation machinery grants local-owner access within the isolated anonymous store. This mode neither changes authenticated stores nor grants external identities. This child does not implement mode conversion. | Real served tests cover create, write, read and restart. Negative tests cover missing default credentials, mixed credentials, remote listeners, alternate transports, store reuse and mode mismatch. This receipt qualifies native TCP only. R003.3 retains private UDS and exhaustive feature-matrix qualification. R003.2 retains performance measurement. The parent row retains mode conversion. |
